# Novel Desk の要件

サーバー版の要件（~/novel-writer/docs/requirements.md）をそのまま当てはめ、ここには Novel Desk だけの要件と前提を書く。

サーバー版の要件のうち、サーバーが無いために当てはめられないものは README の「できないこと」に、サーバー版と画面や動きが違う所とその理由は [server-differences.md](server-differences.md) にあります。

## 1. 前提

- 共同作業者はいない。iPhone と PC は作者専用で、共用しない
- GitHub のアカウントと novel-desk の org の乗っ取りは考えない
- このため、共用の端末と共同作業者だけで起きる問題は扱わない

（2026-10-25 に作者が決めた）

## 2. 要件

1 行に 1 つの要件を書き、ID を付けます。要件を消しても、ID は振り直しません。

### 2.1 セキュリティ（SEC）

| ID | 要件 | 理由 | 確かめ方 | 状態 |
|---|---|---|---|---|
| `DESK-SEC-01` | GitHub App の秘密鍵は、パスキーの PRF から作った鍵で暗号化して保存する。開くたびにパスキーで復号し、取り出せない鍵（extractable: false）にしてメモリーにだけ置く。PRF が無いブラウザーでは、取り出せない鍵のまま保存し、画面でそう伝える | 端末の保存場所を読まれても、パスキーが無ければ秘密鍵を使えないようにするため（秘密鍵には期限が無い） | 試験（tests/ui/appkey.spec.mjs の「DESK-SEC-01: with PRF, the App’s key kept encrypted …」「DESK-SEC-01: the passkey not opening the App’s key …」「DESK-SEC-01: an authenticator without PRF …」「DESK-SEC-01: the App’s key kept by the version before …」の 2 つ、tests/ui/manifest.spec.mjs の「DESK-SEC-01: the passkey made on the press …」、tests/unit の appFormOf・openFailure・APP_KEY_INFO） | 満たす（前の版で暗号化せずに保管した秘密鍵は、取り出せないので暗号化し直せない。今までどおり開き、設定の画面で作り直す手順を出す） |
| `DESK-SEC-02` | 開いている間は、パスキーを求め直さない（ほかのアプリに切り替えて戻ったときも） | iPhone は自分でロックし、開くのに Face ID が要るので同じ役をしている。ロックの解けた iPhone を手にした人は Safari の GitHub やメールも使えるので、Novel Desk だけに足しても守れる範囲がほとんど広がらず、作者は戻るたびに Face ID が 1 回増える | 試験 | 満たす |
| `DESK-SEC-03` | GitHub が GitHub App のトークンを断ったときは、作者がログアウトするまで、この端末の作品の控え・設定・記録・書きかけを消さない。GitHub がまた受け付ければ、作品は前と同じブランチと送る頻度のまま続く。サーバー版の NFR-SEC-16（セッションが切れたときに控え・キャッシュ・記録を消す）とは違う | この版で同じように消すと、送る頻度と選んだブランチも消え、書きかけが既定のブランチへ自動で送られてしまうため | 試験（tests/ui/leave.spec.mjs の「the App’s tokens refused …」） | 満たす |
| `DESK-SEC-04` | GitHub から読んだ novel.toml で、ページのすべてのオブジェクトが共通に持つ値（Object.prototype）を書き換えさせない。キー「__proto__」は読めないキーとして伝え、ほかのキーは表が自分で持つキーとしてだけ見る | 誰の公開リポジトリでもインポートで開けるので、細工した novel.toml を開くと、GitHub への要求のメソッドや、作品の送り先のブランチが書き換わるため（2026-10-26 のセキュリティ点検で見つけた） | 試験（tests/unit/toml.test.mjs の「toml: 「__proto__」 not read …」） | 満たす |

### 2.3 運用（OPS）

| ID | 要件 | 理由 | 確かめ方 | 状態 |
|---|---|---|---|---|
| `DESK-OPS-01` | novel-desk の org には、novel-desk.github.io のほかに GitHub Pages を置かない | 同じ origin になり、端末に保存した鍵と書きかけをそのサイトのスクリプトから使われるため | GitHub の API で org の Pages とメンバーを見る | 満たす（2026-10-25 に GitHub の API で、org の Pages が novel-desk.github.io だけ、メンバーが作者 1 人であることを確かめた） |
| `DESK-OPS-02` | 始めるとき（GitHub App を作るとき）に利用規約を出し、同意するまで先へ進めない。規約を変えたら、始めた後の端末でも開いたときにもう一度同意を求める。規約には、作者個人が事業としてではなく無料で公開しているベータ版であること、公開を急にやめることがあること、作者のもとにデータが残らないこととソースコードの URL、鍵の管理は利用者の責任であること、作者は一切の責任を負わないことを書く。設定の画面から規約を読み返せる | 誰でも開ける場所に公開しているため（2026-10-26 に作者が決めた） | 試験（tests/ui/terms.spec.mjs） | 満たす |
| `DESK-OPS-03` | 設定の画面の「GitHub」で、連携の状態を開くたびに GitHub に確かめ、GitHub が断ったとき（GitHub で App を消したとき）は連携が切れていると出し、その場で始め直せる（ログアウトして最初の画面へ）。同じ欄に、連携をやめる手順（送っていない書きかけを送る、ログアウト、GitHub で App を消す、パスキーを消す）を、その App を消すページへのリンク付きで出す。App がどのリポジトリにもインストールされていないときはそう出し、App をインストールするリポジトリを選ぶ GitHub のページへのリンクを同じ欄に置く。作品を開けないときと、作ったリポジトリを読めないときの文は、このリンクを案内する。パスキーで開けないときの文は、パスキーを削除した場合の抜け方（ログアウトして App を作り直す）を出す。ログアウトの知らせは、GitHub の App とパスキーが残ることを出す | GitHub で連携を消すと、この端末からは何もできなくなる。消す手順と、消した後に始め直す手段が、アプリの中に要る（2026-10-27 に作者が決めた） | 試験（tests/ui/leave.spec.mjs） | 満たす |
| `DESK-OPS-04` | 始め方は GitHub App を作る方法だけにし、トークンで始める方法は設けない。前にトークンで始めた端末では、開いたときに保管したトークンを消し、最初の画面で、トークンで始める方法が無くなったことと、「GitHub App を作成して始める」で始め直すこと、GitHub のトークンの一覧で前のトークンを消すことを出す。送っていない書きかけと作品の控えは消さない（同じアカウントで App を作ると送れる） | 作者は GitHub App で使っており、作品は全部作者のアカウントのリポジトリにある。トークンの始め方を外して、保守する量を減らす（2026-10-27 に作者が決めた） | 試験（tests/ui/token.spec.mjs の「DESK-OPS-04: a device started with a token …」） | 満たす |
| `DESK-OPS-05` | 次の画面に移るまで時間のかかる操作では、行っている手順を画面に出す。「GitHub App を作成して始める」と「パスキーで開く」は押したボタンに、パスキーで開いた後と GitHub から戻った後は読み込み中の画面に、作品を開いたときは読み終わるまで本文の欄に出す | 前の画面が残ったままでは、読み込み中か分からない（2026-10-27 に作者が決めた） | 試験（tests/ui/leave.spec.mjs の「DESK-OPS-05 …」） | 満たす |
