# エージェントに任せるときの手順

このリポジトリで作業を任されたエージェントは、この手順に従います。任せる側は、指示に「docs/agent-checklist.md に従う」と書き、作業の中身だけを書きます。

## 作業の前

- 慣れない書き方が要るときは、ゼロから書かず、GitHub のオープンソースのプロジェクトでやり方を比べてから選び、報告に書く
- 秘密（トークン、メールアドレス、作品の本文）をリポジトリに入れない
- 試験は偽の GitHub（tests/ui/lib/fake-github.mjs）だけを使う。本物の github.com や api.github.com には送らない

## 直すとき

- 複数のファイルにまたがる一括置換（sed -i、スクリプトでの replace）を使わない。1 つのファイルの 1 か所と分かっている置換だけ使ってよい
- 決める部分は lib/ の純粋な関数にし、tests/unit/ で試す（C0・C1 100%）。ui/ には、画面の部品とつなぐ薄いコードだけを置く
- 画面の試験の準備は、画面を操作せずに状態を直接入れる（tests/ui/lib/test.mjs の keptApp、openWork）。GitHub App を作る流れは、それを確かめる試験だけがたどる
- 画面の試験では、前の操作が終わったことを確かめてから次へ進む。端末に書いたことは stored() で確かめてから読み込み直す。ページの移動を止めたまま、その移動を始める操作（click など）を実行しない
- 試験の名前かすぐ上のコメントに、要件の ID を書く。足した試験は、直す前のコードでは失敗することを確かめる
- 文書と画面の文言は日本語。主語と目的語を省かない。比喩を語として使わない。和文の括弧は全角。画面の文言は「作成する」「削除する」「保存する」のように口語を避ける
- 試験の実行中はファイルを変えない。重い試験を 2 つ同時に実行しない

## 確かめる順番

PATH は `$HOME/.local/node/bin:$PATH`。

1. 作業の途中は `npm run check:all`（2 分弱。整形、書き方、型、サーバー版との違い、単体試験、性質の試験、変異テスト）を何回実行してもよい。画面の試験は、関係するファイルだけを `npx playwright test tests/ui/<ファイル>` で実行する
2. 終える前に `npm run check:ui` を 1 回実行する（7 分ほど。変えた画面の試験を 3 回ずつ、画面の試験の全部、JS 全体の C0・C1 100%、記録の点検）
3. check:ui が失敗したら、`npx playwright test --last-failed` で失敗した試験だけを直し、`--repeat-each=3` で通ることを確かめてから、check:ui をもう一度実行する
4. check:ui は 2 回までにする。2 回目も失敗したら、作業を止めて、失敗した試験と原因を報告する
5. check:all と check:ui は、最後の行（「全部通りました」と秒数、画面の試験の passed / failed）まで読む。時間が前回より大きく増えて止まったら、理由を調べて報告する

## 終えるとき

- commit と push はしない。作業ツリーに変更を残して終える（任せる側が差分を読んでから push する）
- 報告は日本語で、表を使わない。番号を振る。次を書く
  1. 直したこと（ファイルと要点）
  2. 足した試験・消した試験と、直す前のコードで失敗することを確かめたか
  3. 文書の直し
  4. check:ui を何回実行したか、最後の数行（そのまま貼る）
  5. 迷って自分で決めたこと
