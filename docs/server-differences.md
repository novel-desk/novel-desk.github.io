# サーバー版との違い

Novel Desk は、サーバー版の Novel Writer（`~/novel-writer` の `public/`）と同じ見た目・同じ文言・同じ操作になるように作っています。作者が 2 つの使い方を覚えなくて済むようにするためです。

違うのは、サーバーが無いためにどうしても同じにできない所（A）と、作者が決めた所（B）だけです。ここに番号を付けて 1 つずつ書きます。Novel Desk だけの要件と前提は [requirements.md](requirements.md) にあります。

## 機械で止める仕組み

`npm run check:all` の「サーバー版との違い」（`tools/server_diff.mjs`）が、サーバー版の `style.css` と `index.html` を Novel Desk のものと比べます。

- 比べる相手は、`tools/server-diff-allowed.txt` の `commit` の行に書いたサーバー版の commit です。`~/novel-writer`（環境変数 `NOVEL_WRITER_DIR` で変えられます）から `git show` で読みます。サーバー版のフォルダには書き込みません
- `style.css` は、規則の単位で比べます。`@media` の中かどうかとセレクター 1 つごとに、最後に効く値を属性ごとに比べます。改行・空白・引用符・規則の並びの違いは、違いにしません
- `index.html` は、要素の単位で比べます。id のある要素は id で、無い要素は親からの道筋で同じ要素とみなし、要素があるか、親、属性、中の文字、子の並びを比べます
- 違いには 1 つずつ鍵が付きます。`tools/server-diff-allowed.txt` に、この文書の番号と一緒に書いた鍵だけを許します
- 許していない違い、もう無くなった違いを許す行、この文書に無い番号を書いた行があると、失敗します
- サーバー版のフォルダや commit が読めないときも、理由を出して失敗します

サーバー版を直したら、Novel Desk も同じに直し、`commit` の行を進めます。違いを足すときは、先にここへ理由を書きます。

画面の JS（`ui/`、`app.js`）は機械では比べていません。文言とボタンと動きは、サーバー版の `public/ui/` と 1 つずつ読み比べて合わせました。

## 各項目の書き方

- サーバー版: サーバー版ではどうなっているか
- Novel Desk: Novel Desk ではどうなっているか
- 理由: なぜサーバーなしでは同じにできないか
- 作者にとって: 使うときに何が違うか

## A1. 始め方（ログインの代わりに、GitHub App・パスキー）

- サーバー版: 「GitHub でログイン」のボタン 1 つで始めます。設定の画面の「アカウント」にユーザー名と「（管理者）」、「GitHub」に「連携済み: ログイン名」と連携のボタンが出ます。管理者には「ユーザーの管理」が出ます。ログアウトは、未送信の書きかけがあるときだけ確かめ、書きかけはこの端末から消します
- Novel Desk: 最初の画面は、ホーム画面に追加する手順（いちばん上）と、「GitHub App を作って始める」です。前にトークンで始めた端末では、最初の画面に、トークンで始める方法が無くなったことと始め直し方が出ます（DESK-OPS-04）。開くたびにパスキーで開く画面が出ます。GitHub が GitHub App のトークンを断ったときは、画面の上に知らせが出て、App を作り直す手順を伝えます。コミットの作者は画面の上で決めます。設定の画面の「アカウント」は GitHub のアカウント名、「GitHub」は GitHub App で連携していることと、秘密鍵の保管のし方です（前の版で暗号化せずに保管した App の秘密鍵なら、暗号化されていないことと作り直す手順も出します。DESK-SEC-01）。「ユーザーの管理」はありません。ログアウトは、書きかけがあるときに「消すか、残すか」を聞きます
- 理由: GitHub の OAuth でトークンを受け取る口は、ブラウザーのページからの要求を受け付けません（README の「できないこと」）。ユーザーを預かるサーバーも無いので、管理者もいません。ログアウトして始め直すのは、GitHub App を作り直すときの手順なので、書きかけを残せるようにしています
- 作者にとって: 端末ごとに一度、GitHub App を作ります。開くたびに Face ID（パスキー）が要ります

## A2. 書いたものを端末にためて、「送る」でまとめて送る

- サーバー版: 打つたびにサーバーに保存し、足元は「保存しました」になります。GitHub へは毎日決まった時刻か「push」で送ります。「リリース・GitHub・その他」の中は、リポジトリ・ブランチの行、「push 済み（N 分前）」などの状態、同期の選び方（毎日 push・手動で push・同期しない）と「pull」「push」「マージ」です。見出しの横に「・push 済み」などが出ます
- Novel Desk: 打った文章と操作（話の追加・名前の変更・削除・並べ替え、資料、画像）は、この端末にためます。足元は「GitHub に保存済み」「端末に保存済み（未送信）」「届けられず、端末に保存済み」です（iPhone の幅で入らないときは 2 行にします）。「リリース・GitHub・その他」の中は、リポジトリ・ブランチの行、「GitHub から読みました（時刻）」「送りました（…）」などの状態、「未送信の一覧」、同期の選び方（自動で送る・手動で送る・同期しない）と「送る（件数）」「マージ」です。見出しの横は「・送信済み」「・未送信」「・送信失敗」です。目次と資料の一覧の行に「未送信」の印が付きます。操作のトーストには「（送るまではこの端末だけの変更です）」が付きます。送っている間は、話の追加・名前の変更・削除・並べ替えができません。作品を GitHub から読み終えるまで、目次のボタンを押せません。作品の削除の確かめは「送ってから削除」「送らずに削除」です
- 理由: 保存先のサーバーが無いので、書くたびに GitHub へ送る代わりに端末にため、まとめて 1 つのコミットにして送ります。毎日決まった時刻に送るには、動き続けるサーバーが要ります。送っている間の操作を止めるのは、送り終えたときに、送った変更が操作の下から消えるためです
- 作者にとって: 自動のときは、書く手を止めて 1 分たったときと、画面を離れたときに送ります。送る前の変更は「未送信の一覧」で 1 つずつ確かめ、取り消せます

## A3. GitHub から直接読む

- サーバー版: 再読み込みのボタン（title「サーバーから再読み込み（…）」）でページを読み込み直します。ほかの端末の変更は 10 秒ごとに確かめます。目次と資料の一覧の行には、最初から最終更新が出ます。画像はサーバーの URL で読みます。履歴の GitHub の版には字数が出ます
- Novel Desk: 再読み込みのボタン（title「GitHub から再読み込み（…）」）で、ページは読み込み直さずに GitHub から作品を読み直します（プレビューの場所は残ります）。ほかの所での変更は 1 分ごとに確かめます。目次の行の最終更新は、行が画面に入ったときに GitHub に聞いて後から出します。資料の一覧の行には最終更新を出しません。画像は GitHub から読んでから出します。履歴の GitHub の版には字数を出しません。記録は、この端末で書いた日と GitHub のコミットから作ります
- 理由: ファイルごとの最終更新や、版ごとの字数を出すには、ファイル・版の数だけ GitHub の API を呼ぶ必要があり、API の回数の上限（1 時間に 5,000 回）にすぐ当たります。確かめる間隔を 1 分にしているのも同じ理由です
- 作者にとって: 資料の一覧と履歴の GitHub の版で、出る情報が少し少なくなります。ほかの端末の変更が出るまで、最大 1 分かかります

## A4. リポジトリを作る・名前を変える

- サーバー版: 新しい作品は題名だけで作ります。GitHub のリポジトリは「GitHub リポジトリを作成・接続」で作り、名前の変更は prompt で新しい名前を聞きます
- Novel Desk: 作品の一覧で題名を入れて「作成」を押すと、ダイアログでリポジトリ名・持ち主・Administration の権限があるトークンを聞きます。名前の変更も、新しい名前とそのトークンをダイアログで聞きます
- 理由: リポジトリを作る・名前を変えるには Administration の権限が要ります。GitHub App には付けないので、その時だけ Administration の権限があるトークンを入れてもらいます（端末には残しません）
- 作者にとって: 作品を作るときと名前を変えるときだけ、Administration の権限があるトークンを用意します

## A5. 作品の一覧はこの端末ごと

- サーバー版: 作品はサーバーにあり、一覧は最初から全部出ます。空のときは「まだ作品がありません。上にタイトルを入力して「作成」を押してください。」です。「GitHub リポジトリをインポート」は、サーバーにリポジトリを取り込みます。作品が GitHub につながっていなければ「GitHub 未接続」と出ます
- Novel Desk: 一覧は、この端末で開いたリポジトリです。空のときは「…「作成」を押すか、「GitHub リポジトリをインポート」から作品のリポジトリを開いてください。」です。各行は、GitHub から読み終えるまで「読み込み中…」や「空のリポジトリです（…）」と出ます。「GitHub リポジトリをインポート」は、そのリポジトリをそのまま開きます。目次の「GitHub の欄」（リポジトリ・ブランチの行と送る行）は、HTML に最初から置きます
- 理由: サーバーに作品の写しを置かないので、一覧はこの端末が覚えているリポジトリになり、中身は 1 つずつ GitHub から読みます。作品はいつも GitHub のリポジトリなので、「未接続」の状態がありません
- 作者にとって: 別の端末で作った作品は、一度「GitHub リポジトリをインポート」から開くと一覧に載ります

## A6. novel.toml を端末で読む

- サーバー版: novel.toml はサーバーが読み、古い形式の作品はサーバーが作り直します
- Novel Desk: novel.toml の読めない所（何行目の何か）を、目次の上の赤い枠に出します
- 理由: サーバーが無いので、端末で novel.toml を読みます。読めない所を作り直すには GitHub に送る必要があるので、作者に知らせて直してもらいます
- 作者にとって: novel.toml を GitHub や Working Copy で書き間違えたとき、目次の上に出ます

## A7. この端末にまだ無い話・UTF-8 でない話

- サーバー版: 話を開けないときは「話を開けませんでした: …」とトーストを出します。ほかの文字コードの話は、サーバーが取り込むときに UTF-8 に変えます
- Novel Desk: その話を開いて本文の欄を使えなくし、本文の上に「この話はまだこの端末に読み込まれていません（つながってから開いてください）」か「文字コードが UTF-8 ではないため開けません」を出します
- 理由: オフラインで、まだ GitHub から読んでいない話は、この端末にありません。サーバーの控えに当たる物がありません
- 作者にとって: 電車の中などで、まだ開いたことのない話を開いたときに出ます

## A8. ページに書いたスクリプトを実行しない（CSP）

- サーバー版: index.html の中に書いたスクリプトで、iOS で拡大しないようにし（viewport に maximum-scale=1）、ページが出る前に画面の色を当て、画面のモジュールが動かなかったときに 1 回だけ読み込み直します
- Novel Desk: 同じ 3 つを `boot.js` という別のファイルで、同じ所（ページの頭）から実行します。index.html には、通信先を GitHub の API に限る Content-Security-Policy と、referrer を送らない meta があります
- 理由: GitHub App の秘密鍵とトークンを持つページなので、このサイトのファイルのほかのスクリプトを実行しないようにしています。そのため、ページに書いたスクリプトは動きません
- 作者にとって: 動きは同じです

## A9. 新しい版の確かめ方

- サーバー版: 60 秒ごとにサーバーの版を聞き、新しい版なら（書きかけが無いとき）読み込み直します
- Novel Desk: service worker が新しい版を見つけたら、同じ条件で読み込み直します
- 理由: 版を答えるサーバーがありません
- 作者にとって: 動きは同じです（新しい版に替わるまでの時間が少し違います）

## A10. 履歴・リリース・未送信の一覧のダイアログ

- サーバー版: 1 つのダイアログ（`#versions`）で、題名と中身を替えて、履歴・リリース一覧・未送信の書きかけを出します
- Novel Desk: 同じ見た目のダイアログを 3 つ（`#versions` が履歴、`#releases` がリリース、`#unsent` が未送信の一覧）置きます。見出しと中身の文言は同じです。未送信の一覧の題名は「未送信の変更」です
- 理由: 未送信の一覧に、送る前の変更（A2）を全部出すためです。リリースと履歴は作りの違いだけで、見え方は同じです
- 作者にとって: 未送信の一覧の題名と中身（送る前の変更も出る）が違います。ほかは同じです

## B1. 作者が決めたもの: アプリの名前

- サーバー版: 「Novel Writer」（ホーム画面の名前は「Novel」）
- Novel Desk: 「Novel Desk」（ホーム画面の名前も「Novel Desk」）
- 理由: サーバーの有無とは関係ありません。2 つを見分けるための名前です。2026-10-26 に作者が「Novel Desk」のままにすると決めました（小説の机という意味）
- 作者にとって: 画面の左上、最初の画面、ホーム画面の名前が違います

## B2. 作者が決めたもの: 利用規約とベータ版の表示

- サーバー版: 利用規約はありません
- Novel Desk: 始めるとき（「GitHub App を作って始める」か「パスキーで保管する」を押したとき）に、この端末で同意していなければ利用規約（`#terms`）を出し、「同意して始める」を押すと押したボタンの続きに進みます。「戻る」で最初の画面に戻ります。同意はこの端末に覚え、規約の版（`data-version`。画面には「第 1 版（2026 年 10 月 26 日）」と出します）を上げると、始めた後の端末でも、次に開いたときにもう一度出します。設定の画面に「利用規約」の欄があり、「利用規約を読む」で同じ画面を開けます（そのときは「戻る」で設定に戻ります）。規約には、作者個人が事業としてではなく無料で公開しているベータ版であること、公開を急にやめることがあること、作者のもとにデータが残らないこととソースコードの URL、鍵の管理は利用者の責任であること、作者は一切の責任を負わないことを書いています
- 理由: サーバーの有無とは関係ありません。誰でも開ける場所に公開しているので、使い始める前に規約を読んでもらいます（2026-10-26 に作者が決めた。DESK-OPS-02）
- 作者にとって: 始めるときと、規約を変えたときに「同意して始める」を 1 回押します。Safari のタブで最初の画面を開いても、ホーム画面に追加する手順は規約より先に見えます。設定の画面に欄が 1 つ増えます

## B3. 作者が決めたもの: 連携が切れたときの表示と、連携をやめる手順

- サーバー版: 設定の画面は、連携の状態を確かめません。連携をやめる手順もありません
- Novel Desk: 設定の画面を開くたびに、GitHub に連携を確かめます（GitHub の /app）。GitHub が断ったとき（401 か 404。GitHub で App を消したとき）は「GitHub App の連携が切れています」と出し、ボタン（`#relink`）を出します。「ログアウトして、App を作り直す」で最初の画面に戻ります。GitHub につながらないときと、ほかの失敗のときは、切れたとは出しません。同じ欄の「連携をやめるとき」（`details.leave`、閉じておく）に、送っていない書きかけを送る、ログアウトする、GitHub で App を消す、パスキーを消す、の順の手順を出します。この端末で作った App なら、その App の Advanced のページ（https://github.com/settings/apps/〜/advanced）へのリンクを出します
- 理由: GitHub で連携を消すと、この端末からは何もできなくなります。消す手順と、消した後に始め直す手段を、アプリの中に置きます（2026-10-27 に作者が決めた。DESK-OPS-03）
- 作者にとって: 設定の画面の「GitHub」の欄に、閉じた「連携をやめるとき」が 1 行増えます。連携が切れたときだけ、ボタンが 1 つ増えます
