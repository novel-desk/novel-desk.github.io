# 形式検証のモデル

送る処理の並行の動きを TLA+ で書いたモデルです（NFR-MAINT-03）。モデル検査器の TLC が、起こりうる順番を全部たどり、書いた文章が消える順番が無いかを確かめます。サーバー版の `formal/` と同じ作り方です。

モデルの検査（TLC で全部の順番をたどる）は check:all には入れていません。モデルを変えたときに、手で実行します。モデルとコードが合っているかの検査（トレース検証）は、check:all で実行します。

## モデル

どちらのモデルも、文章を「打った英小文字の集合」として扱います。blob はその中身で決まるので、blob も文章で表します。両方の版を残すことは、2 つの集合を合わせることにあたります。

- `Send.tla`：この端末で書いた話を、ほかの端末や GitHub でも書かれるブランチに送る動きです。対応するコードは `ui/send.js` の sendAll、`ui/desk.js` の sendDrafts・keepText・readIn・自動で送る処理、`lib/merge.js`、`lib/drafts.js` の afterSend です。ブランチは、送る処理が読んだ commit からしか進めません。読んでから進めるまでにブランチが進んでいたら（422）、読み直します。送っている間に打った文字、送る処理の失敗、答えが届かなかった送信、変換中の文字（入力メソッド）、ほかの所での変更の読み込みを含みます。確かめる性質は 3 つです。打った文字とほかの所で書いた文字が消えないこと（`NoLoss`）、下書きが無く送っている途中でもなければ、打った文字が全部 GitHub にあること（`CleanIsSent`）、本文の欄が下書きか読んだ版を出していること（`Shown`）です
- `Rebase.tla`：まだ送っていない操作（話の名前の変更・移動・削除。元の場所のファイルを消し、新しい場所に置く）を、ほかの所で変わったブランチに送る動きです。対応するコードは、`lib/changes.js` の moveFiles・conflictsOf・rebase、`ui/send.js` の Overlapped、`ui/desk.js` の rebaseChanges と apply です。操作したファイルがほかの所で変わっていたら、送りません。読み直したときに操作を取り消し、その中で打った文字は、元の場所の下書きとして残します。確かめる性質は 2 つです。文字が消えないこと（`NoLoss`）、操作の 2 つの変更（元の場所から消す・新しい場所に置く）がそろって残ること（`Whole`）です

設定ファイルは、今のコードの形（`_fixed`）と、壊した形や直す前の形です。壊した形では、TLC がすぐに反例を出します。

- `Send_fixed.cfg`：今のコードです。誤りは見つかりません
- `Send_now.cfg`（`Kept = FALSE`）：直す前のコードです。変換中の文字を下書きに残していませんでした。そのため、ほかの所での変更を読み込んだときと、送る処理が終わったときに、本文の欄が書き換わり、変換中の文字が消えていました。TLC が `NoLoss` の反例を出します（変換中に、ほかの所で書かれ、読み込む）。このモデルを書いたときに見つかり、変換中の入力も、ほかの入力と同じく下書きに残すように直しました
- `Send_forced.cfg`（`Forced = TRUE`）：ブランチを、読んだ commit を確かめずに進める壊した形です。ほかの所で書いた文字が消えます
- `Send_cleared.cfg`（`Cleared = TRUE`）：送り終えたときに、送っている間に打った文字があっても下書きを消す壊した形です。打った文字が消えます
- `Rebase_fixed.cfg`：今のコードです。誤りは見つかりません
- `Rebase_now.cfg`（`Idle = FALSE`）：直す前のコードです。送っている間にも、題名の欄から話の名前を変えられました。送り終えたときに、送る処理が取った下書きの代わりに、名前の変更で消したはずの元のファイルが、中身の無い変更として残っていました。TLC が `Whole` の反例を出します。このモデルを書いたときに見つかり、送っている間は、名前の変更などの操作をしないように直しました（画面に理由を出します）
- `Rebase_unchecked.cfg`（`Checked = FALSE`）：ほかの所で変わったファイルの操作も送る壊した形です。ほかの所で書いた文字が消えます
- `Rebase_dropped.cfg`（`KeptText = FALSE`）：取り消した操作の中で打った文字を残さない壊した形です。打った文字が消えます

作品の一覧の要約の控え（`ui/works.js`）は、モデルにしていません。控えは、読んだブランチの commit ごとに残します。commit はその中身で決まるので、読み込みと書き込みがどう重なっても、古い要約が新しい commit の要約として残ることはありません。

## 実行のしかた

TLC は Java で動きます。`tla2tools.jar` を [tlaplus のリリース](https://github.com/tlaplus/tlaplus/releases)（v1.8.0）から取ってきて、このディレクトリに置きます（コミットはしません）。Java が無い環境では、コンテナで実行します。

```sh
cd formal
podman run --rm -v "$PWD":/w:Z -w /w docker.io/library/eclipse-temurin:21-jre \
  java -XX:+UseParallelGC -cp tla2tools.jar tlc2.TLC -deadlock -workers 4 \
  -config Send_fixed.cfg Send.tla
```

`Send_fixed.cfg` は、この端末の文字 3 つ、ほかの所の文字 2 つ、commit 7 つまでで約 43 万の状態をたどり、数秒で終わります。答えが届かなかった送信は何度でも繰り返せるので、ブランチの commit の数を `Commits` で区切ります（`Bound`）。`Rebase_fixed.cfg` は約 8 万の状態で、すぐに終わります。

## トレース検証

モデルとコードが同じ動きをしているかを、試験の記録で確かめます。check:all で実行します。

1. 画面の試験 `tests/ui/trace.spec.mjs` が、モデルの場面を画面で実際に動かします。空の話から始め、1 回のキー入力で英小文字（a、b、c）を 1 つ打ちます。ほかの所では、話の末尾に x か y を書きます
2. 画面（`ui/trace.js`）が、モデルの手順に当たる所で、手順と、そのあとの画面の値を 1 行ずつ記録します。値は、読んだ commit と blob、送っていない変更、本文の欄です。試験（`tests/ui/lib/trace.mjs`）は、ほかの所で書いたことと、送る処理が進めたあとのブランチを記録します。記録を書くのは、試験がページに記録の関数（`__nwTrace`）を渡したときだけです。`trace.js` は本番の画面にも入っていますが、関数が無いので何も書きません
3. `tools/trace_check.mjs` が、記録をモデルの値に置き換え（モデルごとの置き換えは `tools/trace/<モデル>.mjs`）、`<モデル>Trace.tla` を TLC で実行します。記録を 1 行目から順に、モデルの手順でたどれるかを確かめます

たどれなければ、たどれた最後の行と、そのときのモデルの値を出します。コードがモデルと違う動きをしたか、モデルがコードの動きを入れていないかのどちらかです。

確かめられるのは、試験で実際に起きた順番だけです。そのため `trace_check.mjs` は、最後にモデルごとに、記録でたどった操作を数えます。モデルの操作（`<モデル>.tla` の Next）のうち、どの記録でもたどらなかった操作があれば、その操作を出して失敗にします。数える操作は `<モデル>Trace.tla` の `Steps` に書きます。`Steps` が Next の操作と合わないときと、記録が 1 本も無いモデルがあるときも失敗にします。モデルの値が変わらない行は、どの操作にも数えません。

記録は `test-results/traces/` に書きます。1 行目の `{"model": …}` が、どのモデルの記録かを表します。変換中の文字の場面は、Chrome でだけ記録します。入力メソッドの変換を起こせるのが、Chrome の CDP（`Input.imeSetComposition`）だけだからです。
