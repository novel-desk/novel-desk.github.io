# Novel Desk

サーバーなしで動く、Novel Writer（kurogane255/novel-writer）の JavaScript 版です。GitHub のリポジトリに置いた小説を、話ごとにブラウザーで書き、GitHub へ送ります。
アプリは GitHub Pages から配る静的なファイルだけでできていて、画面は GitHub の API とだけ通信します。

- 公開の場所: https://novel-desk.github.io/
- 作品の形式は、サーバー版の Novel Writer（kurogane255/novel-writer）と同じです（`novel.toml`、「番号_題名.md」、章のフォルダ）
- 画面の見た目・文言・操作は、サーバー版と同じにしています。違うのは、サーバーが無いためにどうしても同じにできない所だけで、[docs/server-differences.md](docs/server-differences.md) に理由と一緒に書いています。`npm run check:all` が、サーバー版の `style.css` と `index.html` と比べて、理由の無い違いがあれば止めます
- 要件は、サーバー版の要件（kurogane255/novel-writer の docs/requirements.md）をそのまま当てはめます。Novel Desk だけの要件と前提は [docs/requirements.md](docs/requirements.md) にあります
- 「GitHub App を作成して始める」を押すと、この端末で同意していなければ先に利用規約を出し、「同意して始める」を押すまで先へ進めません。規約の文は `index.html` の `#terms` にあります。文を変えたら、`data-version` と画面の「第 N 版（日付）」を上げてください。上げると、次に開いたときにもう一度同意を求めます（[DESK-OPS-02](docs/requirements.md)）

## 置き場所について

アプリは組織 novel-desk の `novel-desk.github.io` リポジトリに置き、GitHub Pages で https://novel-desk.github.io/ の直下から配ります。

**novel-desk の org には、このリポジトリのほかに GitHub Pages を置かないでください（[DESK-OPS-01](docs/requirements.md)）。** 同じ origin になり、端末の鍵を使われるためです。
ほかのサイトを置くと、パスキー（rp.id は `novel-desk.github.io`）と、この端末に置いた GitHub App の秘密鍵や書きかけ（IndexedDB）を、そのサイトのスクリプトからも使えてしまいます。

リポジトリは Public で、アプリのページは誰でも開けます。作品は、作品のリポジトリに入れた GitHub App の秘密鍵がなければ読めません。
このリポジトリのコードと試験には、トークン、メールアドレス、作品の本文を入れません（試験の作品は試験のために作った短い文です）。

## 作者がすること

### 1. GitHub App を作成して始める

作者がするのは、次の 3 つだけです。

1. Novel Desk の最初の画面で「GitHub App を作成して始める」を押す（パスキーに対応する端末では、ここでパスキーを作ります。iPhone なら Face ID を使います）
2. 開いた GitHub の画面で「Create GitHub App」を押す（GitHub にログインしていないときは、先に GitHub がログインを求めます）
3. 続けて開く GitHub の画面で、作品のリポジトリを選び（Only select repositories）、「Install」を押す

Novel Desk に戻ると、作品が開きます。App を入れたリポジトリが 1 つなら、アプリはそのリポジトリを開きます。2 つ以上なら、「リポジトリを開く」の一覧を出します。作者はトークンを手で作らずに、GitHub と連携できます（FR-GH-01）。

アプリは、そのあいだに次のことをします。

- 作者の個人のアカウントに、Novel Desk 専用の GitHub App を作る。GitHub の manifest flow（App の設定を書いた manifest を GitHub に送り、GitHub に App を作らせる方法）を使います。App の名前は「Novel Desk」の後ろに、作った端末の種類、作った日（月と日の 4 桁）、6 文字のランダムな文字を付けたものです（例: 「Novel Desk iPhone 1025 a1b2c3」）。端末の種類は iPhone・iPad・Mac・Windows・Android・Linux のどれかで、分からないときは付けません。端末をなくしたときに、GitHub の App の一覧でどの端末の App かを見分けるためです。ランダムな文字は、App の名前が GitHub 全体で 1 つずつしか使えないために付けます。名前は、GitHub の上限の 34 文字に収まります（いちばん長くて 30 文字）。権限は Contents の読み書きと Metadata の読みだけで、Webhook は使いません。App を入れられるのは、作ったアカウントだけです（public: false）
- GitHub が戻したコードで、App の ID と秘密鍵を受け取る。コードは 1 回だけ、App を作ってから 1 時間だけ使えます。アプリは受け取った秘密鍵をすぐに、最初に作ったパスキーで暗号化して IndexedDB に置き（下の「GitHub App の秘密鍵の置き方」）、秘密鍵の文字列と client secret はどこにも残しません。作者が .pem ファイルを見ることも、移すことも、消すこともありません
- GitHub に送るときに作った state（ランダムな値）をこの端末に覚え、GitHub から戻ったときに同じ値かを確かめる。値が違うとき、1 時間を過ぎたとき、もう使ったときは受け取りません。コードと state は、受け取ったらアドレスから消します（ブラウザーの履歴にも残しません）
- コミットの作者を決める。作品を初めて開いたときに、そのリポジトリの最新のコミットの作者（名前とメールアドレス）を使います。画面の上に出すので、変えるときはそこで書き換えて「これでよい」を押します。リポジトリが空のときは、App を入れたアカウントの名前と noreply のアドレスを使います。メールアドレスをアプリに書き込んではいません
- GitHub で Install を押さずに戻ったときは、「GitHub で作品のリポジトリを選ぶ」の画面を出す。GitHub で App を入れてから Novel Desk に戻ると、アプリは入れたリポジトリを読み直して続けます

秘密鍵には期限が無いので、トークンのように 90 日ごとに作り直す必要はありません。アプリは秘密鍵で 9 分間だけ使える署名（JWT）を作り、GitHub から 1 時間だけ使えるトークンを受け取って使います。トークンは、切れる 5 分前と、GitHub が拒否したときに受け取り直します。どれもページの中で行い、サーバーは使いません。GitHub の API は、App の作成のコードの受け取りとトークンの受け取りのどちらでも、ブラウザーのページからの要求を受け付けます。

#### iPhone のホーム画面のアプリで始めるとき

ホーム画面のアプリと Safari のタブは、保存場所が別です。先にホーム画面に追加し、ホーム画面の Novel Desk で「GitHub App を作成して始める」を押してください。

iOS のホーム画面のアプリから github.com を開くと、アプリの上に Safari の画面（Safari View Controller）が重なって開きます。Novel Desk のアドレスに戻ると、その画面が閉じてアプリの画面で続きを開くと報告されています（Apple の WWDC23 の説明と開発者の報告による。この README を書いた時点では、実機で確かめていません）。重なった画面は、ホーム画面のアプリとも Safari とも別に GitHub のログインを持つことがあり、その場合は GitHub がログインを求めます。

GitHub から戻った画面が、始めた所とは別の所（Safari など）で開いたときは、その画面は App を受け取らず、「始めた Novel Desk に戻ってください」とコードを出します。「コードを写す」を押し、ホーム画面の Novel Desk に戻って、最初の画面の「コード」に貼り、「続ける」を押してください。コードは、GitHub App を作ってから 1 時間だけ使えます。重なった画面を「完了」で閉じて戻ったときも、アプリは App の鍵が置かれたかを確かめて続けます。

### 前にトークンで始めた端末

トークンで始める方法は、2026-10-27 に外しました（[DESK-OPS-04](docs/requirements.md)）。前にトークンで始めた端末で Novel Desk を開くと、アプリは保管していたトークンを消し、最初の画面に、トークンで始める方法が無くなったことと始め直し方を出します。「GitHub App を作成して始める」で始め直してください。送っていない書きかけと作品の控えは消さないので、同じ GitHub のアカウントで App を作ると、書きかけを送れます。前のトークンは、GitHub のトークンの一覧（https://github.com/settings/personal-access-tokens）で消してください。

### GitHub App の秘密鍵の置き方

- 秘密鍵は、その鍵のために作ったパスキーの PRF 拡張の出力から HKDF で作った AES-GCM の鍵で暗号化し、IndexedDB に置きます（[DESK-SEC-01](docs/requirements.md)）。置くのは credential ID、salt、iv、暗号文（秘密鍵の PKCS#8 のバイト列を暗号化したもの）だけです。秘密鍵の文字列、PKCS#8 のバイト列、WebCrypto の鍵は置きません。端末の保存場所を読まれても、パスキーが無ければ秘密鍵を使えません
- 開くたびにパスキーで復号し、すぐに WebCrypto の取り出せない鍵（extractable: false）にして、ページを開いている間だけメモリーに置きます。復号したバイト列は、鍵にしたらすぐ 0 で埋めます。開いている間は、パスキーを求め直しません（DESK-SEC-02）
- 「GitHub App を作成して始める」では、押したときにパスキーを作り、PRF の出力から作った鍵（取り出せない鍵）を、GitHub から戻るまで state と一緒にこの端末に覚えます。この鍵で暗号化するものは、GitHub から秘密鍵を受け取るまでありません。受け取ったら暗号化して置き、覚えた鍵は state と一緒に消します。App を入れて GitHub から戻ったときも、パスキーで開きます
- PRF に対応していないブラウザーや認証器では、秘密鍵を暗号化せず、WebCrypto の取り出せない鍵のまま IndexedDB に置きます。この場合はパスキーを使わずに開きます。この端末でそのブラウザーを開ける人は作品を読み書きできるので、設定の画面でそう伝えます（保管してすぐ GitHub の画面へ移るので、トーストは出しません）
- 前の版で保管した秘密鍵（取り出せない鍵をそのまま置き、パスキーは確かめるだけに使っていたもの）は、取り出せないので暗号化し直せません。今までどおりパスキーで開けます。設定の画面の「GitHub」に、暗号化されていないことと、暗号化する手順（ログアウトしてから「GitHub App を作成して始める」で App を作り直し、前の App を GitHub で消す）を出します。開くたびのトーストやダイアログは出しません
- コミットの作者とコミッターは、決めた名前とメールアドレスです。GitHub の画面では、push したのは App として出ます
- 「リポジトリを開く」には、App を入れたリポジトリが出ます
- 「ログアウト」で、秘密鍵もこの端末から消えます。GitHub に作った App は残るので、要らなければ GitHub の Settings → Developer settings → GitHub Apps で消してください

### 端末をなくしたとき

なくした端末の Novel Desk が GitHub に入れないように、GitHub の側で鍵を消します。なくした端末の画面を見る必要はありません。

- GitHub App で始めたとき: GitHub の [Settings → Developer settings → GitHub Apps](https://github.com/settings/apps) を開きます。なくした端末の App を選び、Advanced の「Delete GitHub App」で消します。App の名前に端末の種類と作った日（例: 「Novel Desk iPhone 1025 a1b2c3」）が入っているので、一覧の名前で見分けられます

消したあとは、なくした端末の Novel Desk は作品を読むことも送ることもできません。手元の端末では、新しく「GitHub App を作成して始める」を押して続けます。

### 作品のリポジトリを作る・名前を変えるときのトークン

アプリの「新しい作品」（リポジトリの作成）と「名前を変更」（リポジトリの名前の変更）には、GitHub の Administration の権限が要ります。GitHub App には付けないので、そのときだけ、GitHub の fine-grained トークンを作って入れてください。

- 作るとき: Repository access を All repositories にし、Repository permissions の Administration を Read and write にする
- 名前を変えるとき: Repository access にそのリポジトリを選び、Administration を Read and write にする

このトークンは、その 1 回の操作にだけ使い、この端末には残しません。期限を短くして作り、使い終わったら GitHub で消してください。作ったリポジトリを開くには、GitHub App をそのリポジトリにも入れてください（GitHub の App の設定の Install App で、リポジトリを足します）。App を入れられるのは App を作ったアカウントだけなので、組織に作ったリポジトリは、この App では開けません。名前を変えたリポジトリには、App はそのまま入っています。

### 2. GitHub Pages を有効にする（最初の 1 回だけ）

リポジトリの Settings → Pages で、Source を Deploy from a branch、Branch を `main`、フォルダを `/ (root)` にして保存します。
コマンドで有効にする場合は次のとおりです。

```sh
gh api -X POST repos/novel-desk/novel-desk.github.io/pages -f 'source[branch]=main' -f 'source[path]=/'
```

main に push すると、数分で https://novel-desk.github.io/ に反映されます。

## 使い方

1. https://novel-desk.github.io/ を開き、「GitHub App を作成して始める」を押す（上の「1. GitHub App を作成して始める」）。パスキーを作る画面が出るので、iPhone なら Face ID で作る
   - iPhone では、先にホーム画面に追加し、ホーム画面のアプリから開いて始めます。Safari のタブとホーム画面のアプリでは保存場所が別になるので、Safari のタブで作った GitHub App の秘密鍵と書きかけは、ホーム画面のアプリからは見えません。Safari のタブで開くと、最初の画面に手順が出ます
2. 作品の一覧（サーバー版の本棚と同じ画面）で作品を選ぶ。開いた作品はアドレス（`#owner/リポジトリ名`）に入るので、ページを読み込み直しても同じ作品を開きます。アドレスに作品が無いとき（ホーム画面から開いたときなど）は、作品の一覧を出します。一覧には、この端末で開いた作品のリポジトリを最終更新の新しい順に出し、作品ごとに題名、字数、話数、最終更新、GitHub のリポジトリ名と使っているブランチ、公開か非公開か（公開は目立たせます）を出します。最後に送れなかった作品には「送信失敗」と出します。ほかのリポジトリは「GitHub リポジトリをインポート」に `owner/リポジトリ名` を入れて「インポート」を押すと開き、一覧に載せます。この欄を開いたときに GitHub に、GitHub App を入れたリポジトリの一覧を問い合わせ、そのうち一覧に無いものを入力の候補に出します。数えた結果はブランチの commit ごとにこの端末に覚え、次からはリポジトリごとにブランチを 1 回問い合わせるだけで出します（変わっていた作品だけ読み直します）。字数は、書く画面と同じく、未送信の書きかけも含めて数えます
3. 目次から話を選んで書く。入力するたびに、書いた文章をこの端末（IndexedDB）に保存します。保存した話には「未送信」と出ます。本文の下には、開いている話が「GitHub に保存済み」「端末に保存済み（未送信）」「届けられず、端末に保存済み」のどれかを出します（FR-SAVE-07）。iPhone の幅でも、右のボタンと並べて切れずに出します。1 行に入らないときは 2 行にします。iPhone の幅で「GitHub に送信」のアイコンが出ているときは、「未送信」「送信失敗」と短く出します。両方の版が並んでいる話では、ここに「両方の版が並んでいます。…」と出します。届けられなかった理由は、目次の下の「リリース・GitHub・その他」の中に出し、見出しの横に「・送信失敗」と出します（「・未送信」「・送信済み」も同じ所に出します）
4. 未送信の変更は、書く手を止めて 1 分たったときと画面を離れたとき（ほかのアプリやタブに切り替えたときなど）に、自動で GitHub に送ります。書く画面だけでなく、資料・プロット・キャラ・記録の画面にいるときも同じです。「送る」（目次の下の「リリース・GitHub・その他」の中。サーバー版の「push」の場所）か、本文の下の「GitHub に送信」のアイコン（未送信の変更があるときだけ出ます）を押しても送れます。どれも、変えた話を全部まとめて 1 つの commit にして、作品のブランチに送ります。送れなかったとき（オフラインなど）は、次に書いたとき、画面を離れたとき、つながったときに送り直します
   - 送る頻度は、作品ごとに「送る」の横で選べ、この端末に覚えます。「自動で送る」（はじめはこれ）、「手動で送る」（「送る」を押したときだけ）、「同期しない」（送ることも、GitHub から取り込むこともしません。作品は、この端末で前に読んだ版を開きます。「送る」と「マージ」は出しません）です
5. 次に開くときは「パスキーで開く」を押し、Face ID を通します

ほかの操作は次のとおりです。

#### 話と本文

- 「プレビュー」（本の形のボタン）: 見出し、箇条書き、ルビ（漢字《かんじ》、|文字《もじ》）、画像を表示します。画像はリポジトリから読みます。切り替えても、読んでいた位置は変わりません
- 「‹ 前の話」「次の話 ›」: 前後の話へ移ります。プレビューでは、最後にある次の話のボタン、左右のスワイプ、端からさらに引っ張る操作（マウスのホイールでも）でも移ります
- iPhone で書いている間は、キーボードの上に入力補助のバー（`「」『』……――`・全角スペース・ルビ・元に戻すとやり直す・プレビュー）が出ます
- 「＋ 話を追加」（目次の下）「＋ 章を追加」（「リリース・GitHub・その他」の中）: 開いている話の章の最後（章の外なら一番下）に話を、一番下に章を足します。番号はサーバー版と同じ決まりで付けます（桁が足りなくなるときは、ほかのファイルの番号を 1 桁増やします）
- 話の題名（本文の上）や作品の題名（目次の上）を書き換えると、題名を変えます。`title = "heading"` なら本文の 1 行目を、`naming = "number"` か題名の無いファイル名なら novel.toml の `[titles]` を、それ以外はファイル名を変えます
- ごみ箱のボタン: 話を作品の `_trash/` へ移します（消えません）
- 目次の各話の行には、サーバー版と同じく最終更新の時刻を出します（ほとんどの話と同じ時刻なら出しません）。時刻はその話を変えた最後の commit で、行が画面に入ったときに GitHub に問い合わせ、話の版（blob）ごとにこの端末に覚えます。未送信の話は、この端末で書いた時刻です
- 「並べ替え」: ↑↓、章への移動、ドラッグで並べ替えます（番号を付け直します）。章の ✎ で章の題名を変えます。章の行を押すと折りたたみ、この端末に覚えます
- 画像のボタン（本文の下）: 選んだ画像を端末で縮め（長い辺 1600px の JPEG。GIF はそのまま。5 MB まで）、作品の画像のフォルダに置き、カーソルの所に `![](…)` を入れます。画像のフォルダは `[images] dir` です。無ければ一番上の `images/`、それも無ければ `[notes] dir` の `images/` に置きます

#### 資料・プロット・キャラ・記録

- 「資料」（目次の下）: 資料のフォルダ（`[notes] dir`）の .md と画像の一覧です。よく使う資料（プロット・キャラクター・世界観・設定）を先頭に、残りをフォルダごとに出します。資料は開いて書き、プレビューできます。「＋ 資料を追加」で作ります（ファイル名は英数字、1 行目の見出しは入れた名前。「フォルダ/名前」でフォルダに入れます）。✎ で名前を変えます（プロットの資料はファイル名だけを変え、`[plot] file` も直します）。ごみ箱のボタンで `_trash/` へ移します。資料にも履歴と画像の挿入があります
  - 画像: 「名前を変更」すると、その画像を使っている本文と資料の `![](…)` も新しい名前にします。「削除」は、使っている箇所の数を出してから、画像を作品の `_trash/` へ移します
- 「プロット」: プロットの資料（`[plot] file`、無ければ名前か見出しに「プロット」「plot」がある資料）を、大箱（`# `）と中箱（`## `）のカードで出します。箱の追加・削除（⋯ の後ろ）・↑↓、1 つの箱だけを開いて書く（「編集」かダブルタップ。「全体」で資料全体に戻ります）ことができます。中箱には、対応する話（`[plot.links]` で対応付けた話と、題名が同じ話）が出て、押すとその話を開きます。対応する話が無い中箱からは「新しい話を作成」できます（大箱の見出しにある章に作り、対応付けます）。「ファイル」でどの資料をプロットにするかを選び、資料が無ければ作れます。本文の上のボタンで、その話の中箱を本文の上に出し、「中箱を変更」で対応付けを変えます
- 「キャラ」: キャラクターの資料（`[characters] file`、無ければ名前か見出しに「キャラ」「人物」「character」がある資料）を、見出しごとに 1 人のカードで出します。「編集」でその人の部分だけを書き、「人物を追加」で資料の最後に見出しを足し、↑↓ で並べ替えます。資料が無ければ作れます
- サーバー版のキャラの画面は、未送信の書きかけがある間は人物を足さず、並べ替えません（サーバーに書くため）。この版では、どの変更もこの端末の未送信の変更なので、書きかけにそのまま足し、並べ替えます
- 横の資料（PC と iPad の横向き、1180px 以上の幅のとき）: 本文の上のボタンで、本文の右に資料の一覧と、選んだ資料のプレビューを出します。作品ごとにこの端末に覚えます。欄の幅は境目をドラッグ（キーボードでは ← →）して変えられます
- 「記録」: 日ごと（直近 30 日）と月ごとに増えた字数を、棒グラフと表で出します。その日の終わりの合計の字数から、前の日の終わりの合計を引いたものです。この端末で書いた日は書くたびに残し、それより前の日は、最初に開いたときに GitHub の commit（その日の最後の commit、300 個まで）から数えます

#### 送る・履歴・リリース

- 「リリース」（目次の下）: 「リリースを作成」で、GitHub にある今の原稿に次のタグ（v1、v2 …）を付け、GitHub のリリースを作ります（未送信の変更があるときは、先に送ります）。「リリース一覧」で、リリースの各話を読み、今の原稿に戻せます（戻すのも未送信の変更になります）
- 履歴のボタン（本文の下）: この話の版を一覧にします。GitHub の版（この話を変えた commit）、この端末に残した版（書いている間、10 分ごとに 1 つ）、未送信の版です。版ごとに、前の版との差分、今の本文との差分、全文を見られ、「この版を復元」で本文に戻せます。戻す前の本文は、この端末の版に残ります
- 次の操作も、書いた文章と同じくこの端末に「未送信」としてためておき、「送る」で 1 つの commit にまとめて送ります
  - 話と章の追加・題名の変更・削除・並べ替え
  - 画像と資料の追加・名前の変更・削除
  - プロットとキャラの変更
  - 履歴とリリースからの復元
- 「未送信の一覧」（「リリース・GitHub・その他」の中）: 未送信の変更を、書いた文章ごと・操作ごとに出します。「取り消す」で、その変更をこの端末から捨てます。操作を取り消しても、その中で書いた文章は元の話に残ります（元の場所にも今の場所にも別の書きかけがあるときは、送れなかった文章として残します）。書いた文章を捨てると GitHub の版に戻り、捨てた文章はこの端末の履歴に残ります。送れなかった文章（下の「送るときの動き」）も、ここに全文を出します。送れなかった文章があるときは、サーバー版と同じく、画面の下に「未送信の書きかけが N 件あります」のボタンが出て、押すとこの一覧を開きます

#### GitHub から読む・ブランチ・リポジトリ

- 再読み込みのボタン（目次の上と、本文の上）: GitHub から作品を読み直します（サーバー版はページを読み込み直しますが、この版はページはそのままで作品を読み直します）。未送信の書きかけがある話は、書きかけのまま表示します。プレビューを開いていたら、プレビューのまま、読んでいた位置もそのままです。iPhone の幅で目次を開いているときは、読み直しても目次を閉じません（読み直している間に開いた目次の「資料」なども、そのまま押せます）
- 開いている間も、1 分ごとと、アプリを前に出したときに GitHub でブランチが進んでいないかを確かめ、進んでいたら読み込みます。作品のどの画面（書く画面、資料・プロット・キャラ・記録）でも同じです。書いている話や資料（未送信の書きかけがあるもの）と、カーソルの位置は変えません。開いている資料に書きかけが無ければ、新しい版を出します（カーソルの位置はそのまま。箱や人物だけを書いていたときは、資料全体に戻ります）。開いている資料がほかの所で削除されたときは、資料の一覧に戻り、そう出します
- 「⎇ ブランチ名」（「リリース・GitHub・その他」の中、リポジトリ名の横）: この端末で読み書きするブランチを選びます。無い名前を入れると、今読んでいる版から新しく作ります。選んだブランチは作品ごとにこの端末に覚え、novel.toml の `git.branch` より先に使います。覚えたブランチが GitHub にもう無いとき（マージの後に消したときなど）は、覚えたのをやめて novel.toml の `git.branch`（無ければ既定のブランチ）を開き、そう通知します。未送信の変更はそのまま残ります。「マージ」で、今のブランチをほかのブランチに GitHub 上でマージします（入る commit と、話ごとの字数の変化を先に出します）。どちらも、未送信の変更があるときは、サーバー版と同じく先に送ってから切り替え・マージします（送れなければ、そうしません）
- 日本語のほかの文字コード（Shift-JIS、EUC-JP、ISO-2022-JP、UTF-16）の話と資料は、UTF-8 に変えて開き、未送信の変更にして、次に送るときに UTF-8 で GitHub に送ります。どの文字コードとしても日本語に読めないファイルは、変えずに残し、開けない理由を出します
- 「リリース・GitHub・その他」の中には、作品のリポジトリ名（GitHub のページを開きます）と、公開か非公開かを出します。公開のリポジトリは目立たせます
- 「名前を変更」（「リリース・GitHub・その他」の中、リポジトリ名の横）: GitHub のリポジトリの名前を変えます（Administration の権限があるトークンを入れます）。未送信の変更、この端末の履歴や設定も、新しい名前に移します
- GitHub でリポジトリの名前を変えたり、ほかの持ち主に移したりしたときは、作品を読むときに気づき、新しい名前に合わせます（リポジトリの ID で確かめます）。もとの名前が別のリポジトリになっていて、もとのリポジトリが見つからないときは、送らずに止め、そう出します。GitHub で確かめてから「このリポジトリに再接続」を押すと、いまのリポジトリを作品のリポジトリにして、未送信の変更を送ります

#### 作品の一覧と設定

- 「設定」（作品の一覧の右上）: サーバー版と同じ並びで、次の欄を出します。「画面の色」では、自動・白・黒から選びます（この端末に覚えます。ブラウザーのバーの色も合わせます）。「アカウント」には、GitHub のアカウント名と、この端末の画面の大きさ（幅・高さ・倍率・上下の余白・ホーム画面のアプリかどうか）を出します。「GitHub」には、GitHub App で連携していることと秘密鍵の保管のし方を出します。開くたびに GitHub に連携を確かめ、GitHub が拒否したとき（GitHub で App を消したとき）は連携が切れていると出し、始め直すボタン（「ログアウトして App を再作成」）を出します。App がどのリポジトリにもインストールされていないときは、そう出します。同じ欄の「App をインストールするリポジトリを選ぶ（GitHub）」で、GitHub のその App のインストールのページを開き、作品のリポジトリを足したり外したりできます（作品を開けないときの文も、ここを案内します）。「GitHub」の欄の「連携をやめるとき」に、ログアウトしてから GitHub で App とパスキーを消す手順を出します（この端末で作った App なら、その App を消すページへのリンク付き）。右上の「ログアウト」で、この端末から GitHub App の秘密鍵を消します
- 新しい作品（作品の一覧の一番上）: 題名を入れて「作成」を押し、出てくる画面でリポジトリ名と Administration の権限があるトークンを入れます。アプリは GitHub に非公開のリポジトリを作り、サーバー版の新しい作品と同じファイルを置いて開きます。置くのは、題名を入れた `novel.toml`・`README.md`・`manuscript/01_はじまり.md`・`notes/images/` です。GitHub App をそのリポジトリに入れていないときは、入れる手順を出します。トークンに権限が足りないときは、どの権限が要るかを出します。中身のない（空の）リポジトリを開くと、同じファイルを置いて作品として始めるかを聞きます（始めないと、作品の一覧に戻ります）
- 「‹ 作品」（目次の上）: 作品の一覧に戻ります
- 「この作品を削除」（「リリース・GitHub・その他」の一番下）: 作品を、この端末の作品の一覧から外します（サーバー版の作品の削除）。GitHub のリポジトリは消しません。サーバー版と同じ 1 つの画面で「送ってから削除」「送らずに削除」「やめる」を選びます（同期しない作品は 1 回だけ確かめます）。この端末に残した控え・履歴・設定は消します。消した作品は「GitHub リポジトリをインポート」から開き直せます

#### アプリ全体

- 新しい版のアプリを公開すると、アプリを前に出したときや 1 時間ごとに見つけて入れ替えます。そして書きかけを失わないときに、自動で新しい版で開き直します。書きかけを失わないのは、作品の一覧などの画面にいるときと、書く画面からほかのアプリに切り替えたときです（送っている途中なら送り終わってから）
- ホーム画面に追加すると、全画面のアプリとして開きます（iPhone の Safari なら共有 → ホーム画面に追加）
- 押す部品の大きさは、サーバー版と同じです（サーバー版の要件 NFR-USE-02 の「縦横 44pt 以上」は、サーバー版がまだ満たしていないので、この版も同じ大きさにしています）
- 本文を書く欄の文字は、iPhone の幅でもサーバー版と同じ 14px です。iOS は 16px より小さい文字の欄をタップすると画面を拡大します。そのため、iOS（iPhone・iPad・iPod）のときだけ viewport に `maximum-scale=1` を足して拡大を止めます（サーバー版と同じ。ピンチでの拡大はできます）。サーバー版は index.html に書いたスクリプトで足しますが、Novel Desk は CSP でページに書いたスクリプトを実行しないので、同じことをページの頭で読む `boot.js` でします。画面の色をページが出る前に適用することと、画面のモジュールが動かなかったときに 1 回だけ読み込み直すことも、同じく `boot.js` でします。Android では足しません（ピンチでの拡大まで止まるため）
- 一度開いた作品は、オフラインでも開いて書けます。送るのは、つながってからです

### 送るときの動き

- commit メッセージはサーバー版と同じ形です（例: `10/24 はじまり ＋320字、駅で −12字`。日付は日本時間）
- Git Data API で、blob、tree、commit を作り、ブランチを進めます。force はしません
- 読んだ後にほかの端末がブランチを進めていたら、新しい木を読み直します。ここで変えた話のうち、ほかで変わっていない話は、その上に積み直します
- ほかでも変わっていた話は、どちらの版も消さずに、両方を並べて送ります。並べた所には「――― ここから、ほかの端末で書かれた版 ―――」の行が入り、目次に「競合」と出ます。その行を探して整理してから、もう一度送ってください
- 書いている話や資料が、ほかの端末や GitHub で並べ替え・番号の付け直し・名前の変更で動かされたときは、書いた文章を、動いた先のその話（資料）に入れて送ります。別の話がもとの場所に来ても、そこには入れません。開いている話と資料も、動いた先に移ります（FR-TOC-04、FR-NOTE-05）
  - 見出しで題名を付ける話（`title = "heading"`）と資料は、名前を変えると 1 行目の見出しが変わります。ほかの所で見出しだけが変わっていたときは、書いた文章を新しい見出しの下に入れます（ここでも見出しを変えていたら、ここの見出しのままにします）
- 書いている話や資料がほかの端末や GitHub で削除された（`_trash/` に移された）ときと、もとの場所に別の話や資料ができていてもとの話が見つからないときは、書いた文章を送りません。消された話を元の場所に戻したり、別の話に混ぜたりはしません。書いた文章はこの端末に残し、画面にそう出します。「未送信の一覧」で中身を確かめて、「送信（GitHub の版と並べて残す）」「開いている話の末尾に挿入」「破棄」から選べます（FR-TOC-06、FR-NOTE-06、FR-SAVE-09）。送るときと、ほかの所での変更を読み込んだときに確かめます
  - どの話がどこへ動いたかは、ファイルの中身（blob）がどこへ動いたかで見分けます。中身が変わりながら動いたときは、見出しのほかの本文が同じファイルか、題名（資料は見出し）が同じファイルで見分けます。中身が同じファイルがいくつもあるとき（空の話など）は、題名が同じものを選びます。どれでも 1 つに決まらないときは、送らずに残します
  - 見分けられないときもあります。ほかの所で名前を変えて本文も書き換え、さらにもとの名前で新しい資料を作ったときは、新しい資料に両方の版を並べて送ります。`_trash/` を使わずにファイルを消し、同じ名前で新しいファイルを作ったときも同じです
- 話の追加・題名の変更・削除・並べ替えで動かしたファイルが、ほかでも変わっていたときは、送りません。画面にそう出るので「再読み込み」を押してください。重なった操作を取り消して読み直します。その話に書いた文章は残り、次に送るときに、ほかの版と並べて送ります。操作はやり直してください
- novel.toml は、アプリが書き換える行（`[titles]`、作品の `title` など）のほかは、1 文字も変えません。送るときに、そのとき GitHub にある novel.toml に書き換えを当てます
- 同じ作品を 2 つのタブで開いているとき、送り終わったタブは、この端末に残した書きかけが自分の送った版のままのときだけ消します（IndexedDB の 1 つのトランザクションで読んで比べて消します）。送っている間にほかのタブが書いた版は残り、次に送ります

### 秘密鍵の保管

#### 鍵とパスキー

- GitHub App の秘密鍵は、パスキーの PRF から作った鍵（AES-GCM）で暗号化して置きます（DESK-SEC-01）。PRF が無いときは、秘密鍵を暗号化せずに取り出せない鍵のまま置き、パスキーを使わずに開き、画面でそう伝えます。前の版で暗号化せずに保管した秘密鍵は、今までどおり開き、設定の画面にだけ作り直す手順を出します。詳しくは「GitHub App の秘密鍵の置き方」にあります
- パスキーの名前は、何を開くかと作った日です（例: 「Novel Desk GitHub App 2026-10-25」。前の版でトークンのために作ったパスキーは「Novel Desk トークン 2026-10-25」の形です）。パスワードの管理（iPhone なら設定 → パスワード）で、使っていないパスキーを見分けられます
- 最初に GitHub App の鍵を保管するとき、ブラウザーに、この端末の保存場所（鍵と書きかけ）を消さないように頼みます（`navigator.storage.persist()`）。ブラウザーの答えは画面に出しません

#### ログアウトと書きかけ

- 「ログアウト」（設定の画面の右上）は、この端末から GitHub App の秘密鍵を消します。一緒に、この端末に残した作品の控え（オフライン用の版、読んだファイル、履歴、設定）も消します。送っていない書きかけがあれば、消すか残すかを聞きます（無ければ、サーバー版と同じく聞かずにログアウトします）。GitHub の App と、パスワードの管理（iPhone なら「パスワード」アプリ）のパスキーは残るので、ログアウトの通知でそう伝えます。使わないときは、それぞれ削除してください
- 「ログアウト」で書きかけを残したときは、書きかけごとに、書いたブランチと送る頻度を残します。作品ごとのリポジトリの ID も残します（ログアウトしている間に GitHub でリポジトリの名前が変わり、もとの名前で別のリポジトリが作られても、書きかけをそこへは送りません）。同じアカウントで GitHub App を作り直して作品を開くと、アプリはそのブランチと送る頻度で作品を開きます。書いたブランチが GitHub にもう無いときも、アプリは書きかけをほかのブランチへ自動では送りません。「送る」を押すと、いまのブランチに送るかを確かめます。「⎇」では、書いたブランチにだけ切り替えられます（無ければ作ります）
- GitHub が GitHub App のトークンを拒否したときは、画面の上に通知を出し、作者がログアウトするまで、この端末の作品の控え・設定・記録・書きかけを消しません。GitHub がまた受け付ければ、作品は前と同じブランチと送る頻度のまま続きます（サーバー版の NFR-SEC-16 との違いと理由は [DESK-SEC-03](docs/requirements.md)）
- アプリは、書きかけの持ち主を GitHub のアカウントの番号で覚えます。覚えるのは、GitHub App を作ったアカウント（API の `/app` の `owner.id`。App を入れられるのは作ったアカウントだけなので、入れた先のアカウントと同じです）の番号です。前の版でトークンで始めた端末では、トークンの GitHub のユーザー（API の `/user` の `id`）を覚えています。同じアカウントなら、App を作り直したときも、トークンで始めた端末で App を作ったときも、同じ人として書きかけを続けます。前の版で覚えた形（ユーザー名、または「app:」と App の ID）からは、ユーザー名・App の ID・Client ID のどれかが同じなら同じ人とします
- 書きかけを残したまま、別のアカウントで GitHub App を作ったときは、中身を出さずに、前の人の書きかけを消すかを聞きます。消さないなら、その秘密鍵は保管しません

#### 画面とページ

- パスキーで開いた後、GitHub から戻って App を受け取る間、パスキーなしで鍵を保存した端末で起動したときは、読み込み中の画面に行っている手順を出します。作品を開くと、読み終わるまで本文の欄に「作品を読み込んでいます…」と出します。そのほかの GitHub や端末の保存場所を待つ操作（ブランチ、インポート、リリースの作成、プレビュー、ログアウトなど）は、待ちが 0.3 秒を超えたときだけ、画面上部のバーに、行っている手順を出します（対象は [DESK-OPS-05](docs/requirements.md)）。通知（トースト）は、iPhone の通知と同じく画面の上に出します
- 作品の画像として出すのは、JPEG、PNG、WebP、GIF だけです（SVG は出しません）
- ページには CSP を付けています。スクリプトはこのサイトのものだけを実行し、通信先は `https://api.github.com` だけです
- この端末に残す版（履歴）は、話ごとに新しいものから 100 個までです

## 読む novel.toml の項目

### 本文

- `title`: 作品の題名
- `manuscript.dir`: 本文のフォルダ。中の「番号_題名.md」が話、「番号_題名/」が章
- `manuscript.files`: 話にするファイル名（例 `"[0-9][0-9].md"`。配列も可）
- `manuscript.exclude`: 話から外すファイル（本文のフォルダからのパス）
- `manuscript.title = "heading"`: 話の題名を 1 行目の「# 第1話 題名」から取る
- `manuscript.naming = "chapter-number"`: 「2-09.md」を第 2 章の第 9 話として読む
- `manuscript.naming = "number"`: 新しい話と章を番号だけの名前にし、題名を `[titles]` に書く
- `[titles]`: 話や章の題名（本文のフォルダからのパスをキーにする）
- `git.branch`: 読み書きするブランチ（書いていないときと、GitHub にそのブランチが無いときは、リポジトリの既定のブランチ。無いときは、そう通知します）

### 資料

- `[notes] dir`: 資料のフォルダ
- `[images] dir`: 画像を置くフォルダ
- `[plot] file`: プロットにする資料。`[plot.links]`: 話（本文のフォルダからのパス）と中箱（見出し）の対応。話を動かすと、キーも一緒に動かします
- `[characters] file`: キャラクターの資料

ほかの項目は読み飛ばします。読めない形の novel.toml（文字列を "" で囲んでいない、複数行の文字列など）は、
何行目の何が読めないかを目次の上に出し、本文のフォルダを一番上として読みます。

## できないこと

サーバー版の要件のうち、サーバーが無いとできないものと、その理由です。

- GitHub のアカウントでのログイン（FR-AUTH-01）: GitHub の OAuth のトークンを受け取るエンドポイントが、ブラウザーのページからの要求（CORS）を受け付けないためです。受け付けないのは `github.com/login/oauth/access_token` と、デバイスフローの `github.com/login/device/code` です。受け取るには、ページの代わりに要求を送るサーバーが要ります。この版では、作者のアカウントに GitHub App を作り（manifest flow）、その秘密鍵でインストールのトークンを受け取ります。App を作ったコードの受け取りは `api.github.com` で行うので、ブラウザーから要求できます。トークンを手で作らずに GitHub と連携すること（FR-GH-01）は、この方法でできます（別のユーザー名とパスワードは作りません）
- 管理者、ユーザーの登録の許可と停止、ユーザーの無効化、初回セットアップのリンク、緊急用のログインリンク（FR-AUTH-02〜06）: アカウントを預かるサーバーが無く、ユーザーという考えがありません。誰がどの作品を読み書きできるかは、GitHub App を入れたリポジトリで決まります（FR-AUTH-08 は GitHub が受け持ちます）。ログアウト（FR-AUTH-07）は「ログアウト」のボタンで、この端末から GitHub App の秘密鍵と作品の控えを消します
- ページを閉じている間に送ること、毎日決まった時刻に送ること（FR-SAVE-03 のうちページを閉じている間、FR-GH-03）: 送る処理はこのページの中で動くので、ページを閉じている間は何も動きません。決まった時刻に動かすには、サーバーが要ります。ページを開いている間は、書く手を止めたときと画面を離れたときに自動で送ります
- 同期が続けて失敗したときの通知（OPS-08）: 閉じているページから通知するには、通知を送るサーバー（Web Push）が要ります。開いている間は、送れなかったことと理由を画面に出します
- CSP の frame-ancestors（NFR-SEC-08 のうち）: GitHub Pages では応答にヘッダーを付けられず、frame-ancestors は meta の CSP では適用されません。ほかの CSP（スクリプトはこのサイトのものだけ、通信先は api.github.com だけ、object-src 'none'、base-uri 'none'、form-action 'none'）は meta で付けています
- サーバーの性能・セキュリティ・運用の要件: サーバーとそのマシンについての要件で、サーバーが無いこの版には当てはまりません。対象は NFR-PERF-01・02・04 / NFR-REL-02〜05 / NFR-SEC-01〜04・06・09〜14・17〜19 / NFR-PORT-02〜05 / OPS-01〜19 です

## 作者の判断で当てはめない要件

- 古い形式の作品を開くこと（FR-WORK-07。`.novel.json` の作品、`_没/` のフォルダ）: 作者の判断で、この版では扱いません。作品は `novel.toml` の形式で置きます（[DESK-WORK-01](docs/requirements.md)）

## 開発

開発用のツールだけを npm で入れます。アプリ本体はライブラリを使わず、ビルドもしません。

```sh
npm install
npm run serve       # http://localhost:4173/ で開く
npm run check:all   # 作業の途中で何回も: 整形、書き方、型、サーバー版との違い、単体試験（lib の C0・C1 100%）、性質の試験、保存の処理の変異テスト（2 分弱）
npm run check:ui    # push の前に 1 回: 画面の試験（Chrome と WebKit、4 並列）、ブラウザーで動く JS の C0・C1 100%、トレース検証（7 分ほど）
```

- 決める部分は `lib/` の純粋な関数にし、vitest で試験します（`tests/unit/`。C0・C1 100%）
- 画面は Playwright で試験します（`tests/ui/`）。GitHub の API はモック（`tests/ui/lib/fake-github.mjs`）で、本物の GitHub には通信しません。GitHub App を作る流れは、それを確かめる試験だけが画面でたどり、ほかの試験は App を保存した状態を端末に入れてから始めます（`tests/ui/lib/test.mjs` の `keptApp`）
- 画面の JS（`app.js`、`boot.js`、`sw.js`、`ui/`、`lib/`）は、画面の試験と単体試験を合わせて C0・C1 を 100% にします（NFR-MAINT-02）。画面の試験では、`tools/serve.mjs` がスクリプトを istanbul で計測できる形にして出し、`tools/coverage_all.mjs` が単体試験の記録と合わせます。実行していない行と分岐は `coverage/all/missing.txt` に出力します
- 書いたものを残して送る処理（`lib/` の changes・drafts・merge・sync）は、Stryker の変異テストで確かめます（`npm run test:mutation:save`、NFR-MAINT-02）。コードを少し変えた変異を、単体試験がすべて検出することを確かめます。`lib/` 全体の変異テストは `npm run test:mutation` で、結果は `reports/mutation/` に出ます（サーバー版と同じく、全体には止める基準を付けていません）
- 送る処理と読み込みは、fast-check の性質の試験でも確かめます（`tests/props/`、`npm run test:props`）。本物の `ui/send.js`・`ui/work.js` と `lib/` を、画面の試験と同じ GitHub の API のモックに接続します。1 つは、GitHub の答えが返る順番を fast-check が選び、その間に打った文字とほかの所での書き込みを混ぜます。もう 1 つは、打つ・話の追加・名前の変更・削除・並べ替え・送る・読み直す・ほかの所での書き込みを、でたらめな順番で続けます。どちらも、書いた文字が消えないこと、手で書いた novel.toml の行がそのまま残ること、送る処理が意図しないファイルを消したり変えたりしないことを確かめます。check:all では種を固定して実行します
- 送る処理の並行の動き（送っている間の入力、ほかの所で進んだブランチへの送信、送っていない操作の取り消し）は、`formal/` の TLA+ のモデルで、文章が消える順番が無いことを確かめます。モデルとコードが合っていることは、画面の試験の記録をモデルの手順でたどるトレース検証で確かめます（NFR-MAINT-03、`formal/README.md`）。TLC には `formal/tla2tools.jar`（コミットしません）と、Java か podman が要ります
- WebKit は Playwright の Docker イメージで実行します。`NW_NO_WEBKIT=1` で WebKit を外せます
- パスキーの試験は Chrome の仮想認証器で実行します。WebKit には Playwright から操作できる仮想認証器がないので、Chrome だけで実行します
- オフラインの試験も Chrome だけで実行します。WebKit では、service worker が付いたページの通信を Playwright の route が受け取れず、GitHub の API のモックに届かないためです

ファイルの置き場所は次のとおりです。

- `index.html`、`style.css`、`app.js`: 画面と、GitHub App・リポジトリの選択（`style.css` はサーバー版のものをそのまま使い、Novel Desk だけの部品の規則を後ろに足しています）
- `boot.js`: ページが出る前に実行すること（iOS の拡大を止める、画面の色、モジュールが動かなかったときの読み込み直し）。サーバー版は index.html の中に書いています
- `docs/`: Novel Desk だけの要件（`requirements.md`）と、サーバー版との違い（`server-differences.md`）
- `tools/server_diff.mjs`、`tools/server-diff-allowed.txt`: サーバー版の `style.css` と `index.html` と比べる点検（`npm run check:server`）と、理由のある違いの一覧。サーバー版のフォルダは `NOVEL_WRITER_DIR`（無ければ `~/novel-writer`）で、`git show` で読むだけです
- `ui/`: I/O の層です。IndexedDB・パスキー・GitHub の API とのやり取り、送る処理、トレース検証の記録を受け持ちます。画面は、目次と本文・入力補助のバー・プレビューと前後の話・画像・履歴・資料・プロット・キャラ・横の資料・記録・リリース・ブランチ・未送信の一覧です。`ui/shared.js` は、書く画面（desk.js）がほかの画面に公開する関数をまとめたファイルです
- `lib/`: 純粋な関数です。TOML とその書き換え・novel.toml と目次・未送信の変更・話の追加と題名の変更と削除と並べ替えの決まり（desk.js）を扱います。ほかに、資料と画像・プロット・キャラ・記録・リリース・ブランチ・差分・Markdown・commit メッセージ・積み直し・文字コードを扱います。画面に出す文言と HTML（目次、資料の一覧、横の資料、プロットの箱、キャラのカード、履歴、リリース、作品の一覧、未送信の一覧、設定）、プレビューから前後の話へ移る操作（引っ張る、横にスワイプする、ホイール）の判断、入力補助のバーで入れる文字、送る処理と読み込みで決める部分も、`lib/` に置きます。`ui/` と `app.js` には、画面の部品とつなぐ薄いコードだけを置きます
- `sw.js`、`manifest.webmanifest`: オフライン用の控えと、ホーム画面に追加するための設定
- `formal/`: 送る処理の TLA+ のモデルと、トレース検証のモデル（`tools/trace_check.mjs`、`tools/trace/`）
