# Novel Desk

サーバーなしで動く、Novel Writer（kurogane255/novel-writer）の JavaScript 版です。GitHub のリポジトリに置いた小説を、話ごとにブラウザーで書き、GitHub へ送ります。
アプリは GitHub Pages から配る静的なファイルだけでできていて、画面は GitHub の API とだけ通信します。

- 公開の場所: https://novel-desk.github.io/
- 作品の形式は、サーバー版の Novel Writer（kurogane255/novel-writer）と同じです（`novel.toml`、「番号_題名.md」、章のフォルダ）
- 画面の見た目・文言・操作は、サーバー版と同じにしています。違うのは、サーバーが無いためにどうしても同じにできない所だけで、[docs/server-differences.md](docs/server-differences.md) に理由と一緒に書いています。`npm run check:all` が、サーバー版の `style.css` と `index.html` と比べて、理由の無い違いがあれば止めます
- 要件は、サーバー版の要件（kurogane255/novel-writer の docs/requirements.md）をそのまま当てはめます。Novel Desk だけの要件と前提は [docs/requirements.md](docs/requirements.md) にあります

## 置き場所について

アプリは組織 novel-desk の `novel-desk.github.io` リポジトリに置き、GitHub Pages で https://novel-desk.github.io/ の直下から配ります。

**novel-desk の org には、このリポジトリのほかに GitHub Pages を置かないでください（[DESK-OPS-01](docs/requirements.md)）。** 同じ origin になり、端末の鍵を使われるためです。
ほかのサイトを置くと、パスキー（rp.id は `novel-desk.github.io`）と、この端末に置いたトークンや書きかけ（IndexedDB）を、そのサイトのスクリプトからも使えてしまいます。

リポジトリは Public で、アプリのページは誰でも開けます。作品はトークンがなければ読めません。
このリポジトリのコードと試験には、トークン、メールアドレス、作品の本文を入れません（試験の作品は試験のために作った短い文です）。

## 作者がすること

### 1. GitHub App を作って始める

作者がするのは、次の 3 つだけです。

1. Novel Desk の最初の画面で「GitHub App を作って始める」を押す（パスキーに対応する端末では、ここでパスキーを作ります。iPhone なら Face ID を使います）
2. 開いた GitHub の画面で「Create GitHub App」を押す（GitHub にログインしていないときは、先に GitHub がログインを求めます）
3. 続けて開く GitHub の画面で、作品のリポジトリを選び（Only select repositories）、「Install」を押す

Novel Desk に戻ると、作品が開きます。App を入れたリポジトリが 1 つなら、アプリはそのリポジトリを開きます。2 つ以上なら、「リポジトリを開く」の一覧を出します。作者はトークンを手で作らずに、GitHub と連携できます（FR-GH-01）。

アプリは、そのあいだに次のことをします。

- 作者の個人のアカウントに、Novel Desk 専用の GitHub App を作る。GitHub の manifest flow（App の設定を書いた manifest を GitHub に送り、GitHub に App を作らせる方法）を使います。App の名前は「Novel Desk」、作った端末の種類（iPhone、iPad、Mac、Windows、Android、Linux。分からないときは付けません）、作った日（月と日の 4 桁）、6 文字のランダムな文字にします（例: 「Novel Desk iPhone 1025 a1b2c3」）。端末をなくしたときに、GitHub の App の一覧でどの端末の App かを見分けるためです。ランダムな文字は、App の名前が GitHub 全体で 1 つずつしか使えないために付けます。名前は、GitHub の上限の 34 文字に収まります（いちばん長くて 30 文字）。権限は Contents の読み書きと Metadata の読みだけで、Webhook は使いません。App を入れられるのは、作ったアカウントだけです（public: false）
- GitHub が戻したコードで、App の ID と秘密鍵を受け取る。コードは 1 回だけ、App を作ってから 1 時間だけ使えます。アプリは受け取った秘密鍵をすぐに、最初に作ったパスキーで暗号化して IndexedDB に置き（下の「GitHub App の秘密鍵の置き方」）、秘密鍵の文字列と client secret はどこにも残しません。作者が .pem ファイルを見ることも、移すことも、消すこともありません
- GitHub に送るときに作った state（ランダムな値）をこの端末に覚え、GitHub から戻ったときに同じ値かを確かめる。値が違うとき、1 時間を過ぎたとき、もう使ったときは受け取りません。コードと state は、受け取ったらアドレスから消します（ブラウザーの履歴にも残しません）
- コミットの作者を決める。作品を初めて開いたときに、そのリポジトリの最新のコミットの作者（名前とメールアドレス）を使います。画面の上に出すので、変えるときはそこで書き換えて「これでよい」を押します。リポジトリが空のときは、App を入れたアカウントの名前と noreply のアドレスを使います。メールアドレスをアプリに書き込んではいません
- GitHub で Install を押さずに戻ったときは、「GitHub で作品のリポジトリを選ぶ」の画面を出す。GitHub で App を入れてから Novel Desk に戻ると、アプリは入れたリポジトリを読み直して続けます

秘密鍵には期限が無いので、トークンのように 90 日ごとに作り直す必要はありません。アプリは秘密鍵で 9 分間だけ使える署名（JWT）を作り、GitHub から 1 時間だけ使えるトークンを受け取って使います。トークンは、切れる 5 分前と、GitHub が断ったときに受け取り直します。どれもページの中で行い、サーバーは使いません（GitHub の API は、App の作成のコードの受け取りも、トークンの受け取りも、ブラウザーのページからの要求を受け付けます）。

#### iPhone のホーム画面のアプリで始めるとき

ホーム画面のアプリと Safari のタブは、保存場所が別です。先にホーム画面に追加し、ホーム画面の Novel Desk で「GitHub App を作って始める」を押してください。

iOS のホーム画面のアプリから github.com を開くと、アプリの上に Safari の画面（Safari View Controller）が重なって開きます。Novel Desk のアドレスに戻ると、その画面が閉じて、アプリの画面で続きを開く、と報告されています（Apple の WWDC23 の説明と、開発者の報告による。この README を書いた時点では、実機で確かめていません）。重なった画面は、ホーム画面のアプリとも Safari とも別に GitHub のログインを持つことがあり、その場合は GitHub がログインを求めます。

GitHub から戻った画面が、始めた所とは別の所（Safari など）で開いたときは、その画面は App を受け取らず、「始めた Novel Desk に戻ってください」とコードを出します。「コードを写す」を押し、ホーム画面の Novel Desk に戻って、最初の画面の「コード」に貼り、「続ける」を押してください。コードは、GitHub App を作ってから 1 時間だけ使えます。重なった画面を「完了」で閉じて戻ったときも、アプリは App の鍵が置かれたかを確かめて続けます。

### 1 の代わりに: トークンで始める


GitHub の fine-grained personal access token を 1 つ作ります。作品のリポジトリだけを読み書きできるトークンにします。

いちばん簡単なのは、アプリの最初の画面の「GitHub でトークンを作る」を押すことです。名前、説明、期限（90 日）、Contents の読み書きが入った状態で GitHub の画面が開くので、Repository access で作品のリポジトリを選び、Generate token を押すだけで済みます。手で作るときの手順は次のとおりです。

1. GitHub の Settings → Developer settings → Personal access tokens → Fine-grained tokens を開き、Generate new token を押す
2. Token name に分かる名前（例: `Novel Desk`）を入れ、Expiration（期限）を選ぶ
3. Resource owner に、作品のリポジトリの持ち主を選ぶ
4. Repository access で Only select repositories を選び、作品のリポジトリ（例: my-novel）だけを選ぶ
5. Permissions の Repository permissions で、次の 2 つだけを付ける
   - Contents: Read and write（話を読み、commit を作り、ブランチを進める）
   - Metadata: Read-only（Contents を選ぶと自動で付きます）
6. Generate token を押し、表示された `github_pat_…` をコピーする

トークンを入れるときに、GitHub で選んだ期限の日も入れます（はじめは 90 日後が入っています。期限なしのトークンなら空にします）。GitHub は、ブラウザーのページにトークンの期限を読ませない（API の応答の `github-authentication-token-expiration` を Access-Control-Expose-Headers に入れていない）ので、アプリはこの日を覚えて数えます。

期限の 14 日前からは、画面の上に期限と、GitHub のトークンの一覧（https://github.com/settings/personal-access-tokens）へのリンクを出します。一覧でトークンを作り直し（Regenerate token）、「新しいトークンを入れる」で新しい値を貼ると、最初と同じようにパスキーで暗号化して、今のトークンと入れ替えます。GitHub がトークンを断ったとき（期限切れ、消されたなど）も、同じ知らせと入れ替えの画面を出します。未送信の書きかけは残ります。サーバー版の要件にはこの知らせが無いので、近い FR-GH-01（GitHub との連携）と NFR-USE-01（失敗したときに次にすることを出す）の試験として確かめています。

### 鍵のファイルがあるとき

前に作った GitHub App の秘密鍵（.pem）が手元にあるときは、最初の画面の「鍵のファイルがあるとき」を開き、App ID（または Client ID）、秘密鍵のファイル、コミットに書く名前とメールアドレスを入れて、「秘密鍵を保管する」を押します。App には Contents の読み書きの権限を付け、作品のリポジトリに入れておきます。保管したあとは、.pem ファイルを消してかまいません。

### GitHub App の秘密鍵の置き方

- 秘密鍵は、トークンと同じく、その鍵のために作ったパスキーの PRF 拡張の出力から HKDF で作った AES-GCM の鍵で暗号化し、IndexedDB に置きます（[DESK-SEC-01](docs/requirements.md)）。置くのは credential ID、salt、iv、暗号文（秘密鍵の PKCS#8 のバイト列を暗号化したもの）だけです。秘密鍵の文字列、PKCS#8 のバイト列、WebCrypto の鍵は置きません。端末の保存場所を読まれても、パスキーが無ければ秘密鍵を使えません
- 開くたびにパスキーで復号し、すぐに WebCrypto の取り出せない鍵（extractable: false）にして、ページを開いている間だけメモリーに置きます。復号したバイト列は、鍵にしたらすぐ 0 で埋めます。開いている間は、パスキーを求め直しません（DESK-SEC-02）
- 「GitHub App を作って始める」では、押したときにパスキーを作り、PRF の出力から作った鍵（取り出せない鍵）を、GitHub から戻るまで state と一緒にこの端末に覚えます。この鍵で暗号化するものは、GitHub から秘密鍵を受け取るまでありません。受け取ったら暗号化して置き、覚えた鍵は state と一緒に消します。App を入れて GitHub から戻ったときも、パスキーで開きます
- PRF に対応していないブラウザーや認証器では、秘密鍵を暗号化せず、WebCrypto の取り出せない鍵のまま IndexedDB に置きます。この場合はパスキーを使わずに開きます。この端末でそのブラウザーを開ける人は作品を読み書きできるので、保管したときのトーストと設定の画面でそう伝えます（トークンを PRF なしで置くときと同じです）
- 前の版で保管した秘密鍵（取り出せない鍵をそのまま置き、パスキーは確かめるだけに使っていたもの）は、取り出せないので暗号化し直せません。今までどおりパスキーで開けます。設定の画面の「GitHub」に、暗号化されていないことと、暗号化する手順（GitHub の App の設定で秘密鍵を作り直し、ログアウトしてから新しい秘密鍵で始める）を出します。開くたびのトーストやダイアログは出しません
- コミットの作者とコミッターは、決めた名前とメールアドレスです。GitHub の画面では、push したのは App として出ます
- 「リポジトリを開く」には、App を入れたリポジトリが出ます
- 「ログアウト」で、秘密鍵もこの端末から消えます。GitHub に作った App は残るので、要らなければ GitHub の Settings → Developer settings → GitHub Apps で消してください

### 端末をなくしたとき

なくした端末の Novel Desk が GitHub に入れないように、GitHub の側で鍵を消します。なくした端末の画面を見る必要はありません。

- GitHub App で始めたとき: GitHub の Settings → Developer settings → GitHub Apps（https://github.com/settings/apps）を開き、なくした端末の App を選んで、Advanced の「Delete GitHub App」で消します。App の名前に端末の種類と作った日（例: 「Novel Desk iPhone 1025 a1b2c3」）が入っているので、一覧の名前で見分けられます
- トークンで始めたとき: GitHub のトークンの一覧（https://github.com/settings/personal-access-tokens）で、その端末で入れたトークンを消します（Delete）

消したあとは、なくした端末の Novel Desk は作品を読むことも送ることもできません。手元の端末では、新しく「GitHub App を作って始める」を押すか、新しいトークンを入れて続けます。

### 作品のリポジトリを作る・名前を変えるときのトークン

アプリの「新しい作品」（リポジトリの作成）と「名前を変更」（リポジトリの名前の変更）には、GitHub の Administration の権限が要ります。いつものトークンには付けず、そのときだけ、別のトークンを作って入れてください。

- 作るとき: Repository access を All repositories にし、Repository permissions の Administration を Read and write にする
- 名前を変えるとき: Repository access にそのリポジトリを選び、Administration を Read and write にする

このトークンは、その 1 回の操作にだけ使い、この端末には残しません。期限を短くして作り、使い終わったら GitHub で消してください。作ったリポジトリをいつものトークンで読めないとき（Only select repositories のとき）は、GitHub のトークンの一覧でいつものトークンを開き、Repository access に作ったリポジトリを足してください。

### 2. GitHub Pages を有効にする（最初の 1 回だけ）

リポジトリの Settings → Pages で、Source を Deploy from a branch、Branch を `main`、フォルダを `/ (root)` にして保存します。
コマンドで有効にする場合は次のとおりです。

```sh
gh api -X POST repos/novel-desk/novel-desk.github.io/pages -f 'source[branch]=main' -f 'source[path]=/'
```

main に push すると、数分で https://novel-desk.github.io/ に反映されます。

## 使い方

1. https://novel-desk.github.io/ を開き、「GitHub App を作って始める」を押す（上の「1. GitHub App を作って始める」）。トークンで始めるときは、作ったトークンを貼って「パスキーで保管する」を押す。パスキーを作る画面が出るので、iPhone なら Face ID で作る
   - iPhone では、先にホーム画面に追加し、ホーム画面のアプリから開いて始めます。Safari のタブとホーム画面のアプリでは保存場所が別になるので、Safari のタブで入れたトークンと書きかけは、ホーム画面のアプリからは見えません。Safari のタブで開くと、最初の画面に手順が出ます
2. 作品の一覧（サーバー版の本棚と同じ画面）で作品を選ぶ。開いた作品はアドレス（`#owner/リポジトリ名`）に入るので、ページを読み込み直しても同じ作品を開きます。アドレスに作品が無いとき（ホーム画面から開いたときなど）は、作品の一覧を出します。一覧には、この端末で開いた作品のリポジトリを最終更新の新しい順に出し、作品ごとに題名、字数、話数、最終更新、GitHub のリポジトリ名と使っているブランチ、公開か非公開か（公開は目立たせます）を出します。最後に送れなかった作品には「送信失敗」と出します。ほかのリポジトリは「GitHub リポジトリをインポート」に `owner/リポジトリ名` を入れて「インポート」を押すと開き、一覧に載せます。この欄を開いたときに GitHub にリポジトリの一覧を問い合わせ、トークンで書き込めるもの（読むだけの公開リポジトリは出しません）のうち一覧に無いものを、入力の候補に出します。数えた結果はブランチの commit ごとにこの端末に覚え、次からはリポジトリごとにブランチを 1 回問い合わせるだけで出します（変わっていた作品だけ読み直します）。字数は、書く画面と同じく、未送信の書きかけも含めて数えます
3. 目次から話を選んで書く。入力するたびに、書いた文章をこの端末（IndexedDB）に保存します。保存した話には「未送信」と出ます。本文の下には、開いている話が「GitHub に保存済み」「端末に保存済み（未送信）」「届けられず、端末に保存済み」のどれかを出します（FR-SAVE-07）。iPhone の幅でも、右のボタンと並べて切れずに出します。1 行に入らないときは 2 行にします。両方の版が並んでいる話では、ここに「両方の版が並んでいます。…」と出します。届けられなかった理由は、目次の下の「リリース・GitHub・その他」の中に出し、見出しの横に「・送信失敗」と出します（「・未送信」「・送信済み」も同じ所に出します）
4. 未送信の変更は、書く手を止めて 1 分たったときと、画面を離れたとき（ほかのアプリに切り替えた、タブを替えたなど）に、自動で GitHub に送ります。書く画面だけでなく、資料・プロット・キャラ・記録の画面にいるときも同じです。「送る」（目次の下の「リリース・GitHub・その他」の中。サーバー版の「push」の場所）を押しても送れます。どちらも、変えた話を全部まとめて 1 つの commit にして、作品のブランチに送ります。送れなかったとき（オフラインなど）は、次に書いたとき、画面を離れたとき、つながったときに送り直します
   - 送る頻度は、作品ごとに「送る」の横で選べ、この端末に覚えます。「自動で送る」（はじめはこれ）、「手動で送る」（「送る」を押したときだけ）、「同期しない」（送ることも、GitHub から取り込むこともしません。作品は、この端末で前に読んだ版を開きます。「送る」と「マージ」は出しません）です
5. 次に開くときは「パスキーで開く」を押し、Face ID を通します

ほかの操作は次のとおりです。

- 「プレビュー」（本の形のボタン）: 見出し、箇条書き、ルビ（漢字《かんじ》、|文字《もじ》）、画像を表示します。画像はリポジトリから読みます。切り替えても、読んでいた位置は変わりません
- 「‹ 前の話」「次の話 ›」: 前後の話へ移ります。プレビューでは、最後にある次の話のボタン、左右のスワイプ、端からさらに引っ張る操作（マウスのホイールでも）でも移ります
- iPhone で書いている間は、キーボードの上に入力補助のバー（「」『』……――、全角スペース、ルビ、元に戻す・やり直す、プレビュー）が出ます
- 「＋ 話を追加」（目次の下）「＋ 章を追加」（「リリース・GitHub・その他」の中）: 開いている話の章の最後（章の外なら一番下）に話を、一番下に章を足します。番号はサーバー版と同じ決まりで付けます（桁が足りなくなるときは、ほかのファイルの番号を 1 桁増やします）
- 話の題名（本文の上）や作品の題名（目次の上）を書き換えると、題名を変えます。`title = "heading"` なら本文の 1 行目を、`naming = "number"` か題名の無いファイル名なら novel.toml の `[titles]` を、それ以外はファイル名を変えます
- ごみ箱のボタン: 話を作品の `_trash/` へ移します（消えません）
- 目次の各話の行には、サーバー版と同じく最終更新の時刻を出します（ほとんどの話と同じ時刻なら出しません）。時刻はその話を変えた最後の commit で、行が画面に入ったときに GitHub に問い合わせ、話の版（blob）ごとにこの端末に覚えます。未送信の話は、この端末で書いた時刻です
- 「並べ替え」: ↑↓、章への移動、ドラッグで並べ替えます（番号を付け直します）。章の ✎ で章の題名を変えます。章の行を押すと折りたたみ、この端末に覚えます
- 画像のボタン（本文の下）: 選んだ画像を端末で縮め（長い辺 1600px の JPEG。GIF はそのまま。5 MB まで）、作品の画像のフォルダ（`[images] dir`、無ければ一番上の `images/`、無ければ `[notes] dir` の `images/`）に置き、カーソルの所に `![](…)` を入れます
- 「資料」（目次の下）: 資料のフォルダ（`[notes] dir`）の .md と画像の一覧です。よく使う資料（プロット、キャラクター、世界観、設定）を先頭に、残りをフォルダごとに出します。資料を開いて書き、プレビューし、「＋ 資料を追加」で作り（ファイル名は英数字、1 行目の見出しは入れた名前。「フォルダ/名前」でフォルダに入れます）、✎ で名前を変え（プロットの資料はファイル名だけを変え、`[plot] file` も直します）、ごみ箱のボタンで `_trash/` へ移します。資料にも履歴と画像の挿入があります
  - 画像: 「名前を変更」すると、その画像を使っている本文と資料の `![](…)` も新しい名前にします。「削除」は、使っている箇所の数を出してから、画像を作品の `_trash/` へ移します
- 「プロット」: プロットの資料（`[plot] file`、無ければ名前か見出しに「プロット」「plot」がある資料）を、大箱（`# `）と中箱（`## `）のカードで出します。箱の追加・削除（⋯ の後ろ）・↑↓、1 つの箱だけを開いて書く（「編集」かダブルタップ。「全体」で資料全体に戻ります）ことができます。中箱には、対応する話（`[plot.links]` で対応付けた話と、題名が同じ話）が出て、押すとその話を開きます。対応する話が無い中箱からは「新しい話を作成」できます（大箱の見出しにある章に作り、対応付けます）。「ファイル」でどの資料をプロットにするかを選び、資料が無ければ作れます。本文の上のボタンで、その話の中箱を本文の上に出し、「中箱を変更」で対応付けを変えます
- 「キャラ」: キャラクターの資料（`[characters] file`、無ければ名前か見出しに「キャラ」「人物」「character」がある資料）を、見出しごとに 1 人のカードで出します。「編集」でその人の部分だけを書き、「人物を追加」で資料の最後に見出しを足し、↑↓ で並べ替えます。資料が無ければ作れます
- 横の資料（PC と iPad の横向き、1180px 以上の幅のとき）: 本文の上のボタンで、本文の右に資料の一覧と、選んだ資料のプレビューを出します。作品ごとにこの端末に覚えます。欄の幅は境目をドラッグ（キーボードでは ← →）して変えられます
- 「記録」: 日ごと（直近 30 日）と月ごとに増えた字数を、棒グラフと表で出します。その日の終わりの合計の字数から、前の日の終わりの合計を引いたものです。この端末で書いた日は書くたびに残し、それより前の日は、最初に開いたときに GitHub の commit（その日の最後の commit、300 個まで）から数えます
- 「リリース」（目次の下）: 「リリースを作成」で、GitHub にある今の原稿に次のタグ（v1、v2 …）を付け、GitHub のリリースを作ります（未送信の変更があるときは、先に送ります）。「リリース一覧」で、リリースの各話を読み、今の原稿に戻せます（戻すのも未送信の変更になります）
- 履歴のボタン（本文の下）: この話の版を一覧にします。GitHub の版（この話を変えた commit）、この端末に残した版（書いている間、10 分ごとに 1 つ）、未送信の版です。版ごとに、前の版との差分、今の本文との差分、全文を見られ、「この版を復元」で本文に戻せます。戻す前の本文は、この端末の版に残ります
- 話の追加・章の追加・題名の変更・削除・並べ替え・画像と資料の追加・名前の変更・削除・プロットとキャラの変更・履歴とリリースからの復元は、書いた文章と同じく、この端末に「未送信」としてためておき、「送る」で 1 つの commit にまとめて送ります
- サーバー版のキャラの画面は、未送信の書きかけがある間は人物を足さず、並べ替えません（サーバーに書くため）。この版では、どの変更もこの端末の未送信の変更なので、書きかけにそのまま足し、並べ替えます
- 再読み込みのボタン（目次の上と、本文の上）: GitHub から作品を読み直します（サーバー版はページを読み込み直しますが、この版はページはそのままで作品を読み直します）。未送信の書きかけがある話は、書きかけのまま表示します。プレビューを開いていたら、プレビューのまま、読んでいた位置もそのままです。iPhone の幅で目次を開いているときは、読み直しても目次を閉じません（読み直している間に開いた目次の「資料」なども、そのまま押せます）
- 開いている間も、1 分ごとと、アプリを前に出したときに、GitHub でブランチが進んでいないかを確かめ、進んでいたら読み込みます。作品のどの画面（書く画面、資料・プロット・キャラ・記録）でも同じです。書いている話や資料（未送信の書きかけがあるもの）と、カーソルの位置は変えません。開いている資料に書きかけが無ければ、新しい版を出します（カーソルの位置はそのまま。箱や人物だけを書いていたときは、資料全体に戻ります）。開いている資料がほかの所で削除されたときは、資料の一覧に戻り、そう出します
- 「未送信の一覧」（「リリース・GitHub・その他」の中）: 未送信の変更を、書いた文章ごと・操作ごとに出します。「取り消す」で、その変更をこの端末から捨てます。操作を取り消しても、その中で書いた文章は元の話に残ります（元の場所にも今の場所にも別の書きかけがあるときは、送れなかった文章として残します）。書いた文章を捨てると GitHub の版に戻り、捨てた文章はこの端末の履歴に残ります。送れなかった文章（下の「送るときの動き」）も、ここに全文を出します。送れなかった文章があるときは、サーバー版と同じく、画面の下に「未送信の書きかけが N 件あります」のボタンが出て、押すとこの一覧を開きます
- 「⎇ ブランチ名」（「リリース・GitHub・その他」の中、リポジトリ名の横）: この端末で読み書きするブランチを選びます。無い名前を入れると、今読んでいる版から新しく作ります。選んだブランチは作品ごとにこの端末に覚え、novel.toml の `git.branch` より先に使います。覚えたブランチが GitHub にもう無いとき（マージの後に消したときなど）は、覚えたのをやめて novel.toml の `git.branch`（無ければ既定のブランチ）を開き、そう知らせます。未送信の変更はそのまま残ります。「マージ」で、今のブランチをほかのブランチに GitHub 上でマージします（入る commit と、話ごとの字数の変化を先に出します）。どちらも、未送信の変更があるときは、サーバー版と同じく先に送ってから切り替え・マージします（送れなければ、そうしません）
- 日本語のほかの文字コード（Shift-JIS、EUC-JP、ISO-2022-JP、UTF-16）の話と資料は、UTF-8 に変えて開き、未送信の変更にして、次に送るときに UTF-8 で GitHub に送ります。どの文字コードとしても日本語に読めないファイルは、変えずに残し、開けない理由を出します
- 「設定」（作品の一覧の右上）: サーバー版と同じ並びで、画面の色（自動・白・黒。この端末に覚えます。ブラウザーのバーの色も合わせます）、アカウント（GitHub のアカウント名と、この端末の画面の大きさ: 幅、高さ、倍率、上下の余白、ホーム画面のアプリかどうか）、GitHub（トークンか GitHub App のどちらで連携しているかと、その保管のし方）を出します。右上の「ログアウト」で、この端末からトークンを消します
- 「リリース・GitHub・その他」の中には、作品のリポジトリ名（GitHub のページを開きます）と、公開か非公開かを出します。公開のリポジトリは目立たせます
- 新しい作品（作品の一覧の一番上）: 題名を入れて「作成」を押し、出てくる画面でリポジトリ名と Administration の権限があるトークンを入れると、GitHub に非公開のリポジトリを作り、サーバー版の新しい作品と同じファイル（題名を入れた novel.toml、README.md、manuscript/01_はじまり.md、notes/images/）を置いて開きます。トークンに権限が足りないときは、どの権限が要るかを出します。中身のない（空の）リポジトリを開くと、同じファイルを置いて作品として始めるかを聞きます（始めないと、作品の一覧に戻ります）
- 「名前を変更」（「リリース・GitHub・その他」の中、リポジトリ名の横）: GitHub のリポジトリの名前を変えます（Administration の権限があるトークンを入れます）。未送信の変更、この端末の履歴や設定も、新しい名前に移します
- GitHub でリポジトリの名前を変えたり、ほかの持ち主に移したりしたときは、作品を読むときに気づき、新しい名前に合わせます（リポジトリの ID で確かめます）。もとの名前が別のリポジトリになっていて、もとのリポジトリが見つからないときは、送らずに止め、そう出します。GitHub で確かめてから「このリポジトリに再接続」を押すと、いまのリポジトリを作品のリポジトリにして、未送信の変更を送ります
- 「‹ 作品」（目次の上）: 作品の一覧に戻ります
- 「この作品を削除」（「リリース・GitHub・その他」の一番下）: 作品を、この端末の作品の一覧から外します（サーバー版の作品の削除）。GitHub のリポジトリは消しません。サーバー版と同じ 1 つの画面で「送ってから削除」「送らずに削除」「やめる」を選びます（同期しない作品は 1 回だけ確かめます）。この端末に残した控え・履歴・設定は消します。消した作品は「GitHub リポジトリをインポート」から開き直せます
- 新しい版のアプリを公開すると、アプリを前に出したときや 1 時間ごとに見つけて入れ替え、書きかけを失わないとき（作品の一覧などの画面にいるとき、または書く画面からほかのアプリに切り替えたとき。送っている途中なら送り終わってから）に、自動で新しい版で開き直します
- ホーム画面に追加すると、全画面のアプリとして開きます（iPhone の Safari なら共有 → ホーム画面に追加）
- 押す部品の大きさは、サーバー版と同じです（サーバー版の要件 NFR-USE-02 の「縦横 44pt 以上」は、サーバー版がまだ満たしていないので、この版も同じ大きさにしています）
- 本文を書く欄の文字は、iPhone の幅でもサーバー版と同じ 14px です。iOS は 16px より小さい文字の欄をタップすると画面を拡大するので、iOS（iPhone、iPad、iPod）のときだけ、viewport に `maximum-scale=1` を足して拡大を止めます（サーバー版と同じ。ピンチでの拡大はできます）。サーバー版は index.html に書いたスクリプトで足しますが、Novel Desk は CSP でページに書いたスクリプトを実行しないので、同じことをページの頭で読む `boot.js` でします。画面の色をページが出る前に当てることと、画面のモジュールが動かなかったときに 1 回だけ読み込み直すことも、同じく `boot.js` でします。Android では足しません（ピンチでの拡大まで止まるため）
- 一度開いた作品は、オフラインでも開いて書けます。送るのは、つながってからです

### 送るときの動き

- commit メッセージはサーバー版と同じ形です（例: `10/24 はじまり ＋320字、駅で −12字`。日付は日本時間）
- Git Data API で、blob、tree、commit を作り、ブランチを進めます。force はしません
- 読んだ後にほかの端末がブランチを進めていたら、新しい木を読み直します。ここで変えた話のうち、ほかで変わっていない話は、その上に積み直します
- ほかでも変わっていた話は、どちらの版も消さずに、両方を並べて送ります。並べた所には「――― ここから、ほかの端末で書かれた版 ―――」の行が入り、目次に「競合」と出ます。その行を探して整理してから、もう一度送ってください
- 書いている話や資料が、ほかの端末や GitHub で並べ替え・番号の付け直し・名前の変更で動かされたときは、書いた文章を、動いた先のその話（資料）に入れて送ります。別の話がもとの場所に来ても、そこには入れません。開いている話と資料も、動いた先に移ります（FR-TOC-04、FR-NOTE-05）
  - 見出しで題名を付ける話（`title = "heading"`）と資料は、名前を変えると 1 行目の見出しが変わります。ほかの所で見出しだけが変わっていたときは、書いた文章を新しい見出しの下に入れます（ここでも見出しを変えていたら、ここの見出しのままにします）
- 書いている話や資料が、ほかの端末や GitHub で削除された（`_trash/` に移された）ときと、もとの場所に別の話や資料ができていて、もとの話が見つからないときは、書いた文章を送りません。消された話を元の場所に戻したり、別の話に混ぜたりはしません。書いた文章はこの端末に残し、画面にそう出します。「未送信の一覧」で中身を確かめて、「送信（GitHub の版と並べて残す）」「開いている話の末尾に挿入」「破棄」から選べます（FR-TOC-06、FR-NOTE-06、FR-SAVE-09）。送るときと、ほかの所での変更を読み込んだときに確かめます
  - どの話がどこへ動いたかは、ファイルの中身（blob）がどこへ動いたかで見分けます。中身が変わりながら動いたときは、見出しのほかの本文が同じファイルか、題名（資料は見出し）が同じファイルで見分けます。中身が同じファイルがいくつもあるとき（空の話など）は、題名が同じものを選びます。どれでも 1 つに決まらないときは、送らずに残します
  - 見分けられないときもあります。ほかの所で名前を変えて本文も書き換え、さらにもとの名前で新しい資料を作ったときは、新しい資料に両方の版を並べて送ります。`_trash/` を使わずにファイルを消し、同じ名前で新しいファイルを作ったときも同じです
- 話の追加・題名の変更・削除・並べ替えで動かしたファイルが、ほかでも変わっていたときは、送りません。画面にそう出るので「再読み込み」を押してください。重なった操作を取り消して読み直します。その話に書いた文章は残り、次に送るときに、ほかの版と並べて送ります。操作はやり直してください
- novel.toml は、アプリが書き換える行（`[titles]`、作品の `title` など）のほかは、1 文字も変えません。送るときに、そのとき GitHub にある novel.toml に書き換えを当てます
- 同じ作品を 2 つのタブで開いているとき、送り終わったタブは、この端末に残した書きかけを、自分が送った版のままのときだけ消します（IndexedDB の 1 つのトランザクションで、読んで比べて消します）。送っている間にほかのタブが書いた版は残り、次に送ります

### トークンの保管

- トークンは、パスキーの PRF 拡張の出力から HKDF で作った AES-GCM の鍵で暗号化し、IndexedDB に置きます（置くのは credential ID、salt、iv、暗号文だけです）。開くたびにパスキーで復号し、復号したトークンはページを開いている間だけメモリーに置きます
- PRF に対応していないブラウザーや認証器では、WebCrypto の取り出せない鍵（extractable: false）を IndexedDB に置いて暗号化します。この場合はパスキーを使わずに開きます。この端末でそのブラウザーを開ける人はトークンを使えるので、画面でもそう伝えます
- GitHub App の秘密鍵も、同じやり方（パスキーの PRF から作った鍵、AES-GCM）で暗号化して置きます（DESK-SEC-01）。PRF が無いときは、秘密鍵を暗号化せずに取り出せない鍵のまま置き、パスキーを使わずに開き、画面でそう伝えます。前の版で暗号化せずに保管した秘密鍵は、今までどおり開き、設定の画面にだけ作り直す手順を出します。詳しくは「GitHub App の秘密鍵の置き方」にあります
- パスキーの名前は、何を開くかと作った日です（例: 「Novel Desk トークン 2026-10-25」「Novel Desk GitHub App 2026-10-25」）。パスワードの管理（iPhone なら設定 → パスワード）で、使っていないパスキーを見分けられます
- 最初にトークンか GitHub App の鍵を保管するとき、ブラウザーに、この端末の保存場所（鍵と書きかけ）を消さないように頼みます（`navigator.storage.persist()`）。ブラウザーの答えは画面に出しません
- 「ログアウト」（設定の画面の右上）は、この端末からトークンを消します。一緒に、この端末に残した作品の控え（オフライン用の版、読んだファイル、履歴、設定）も消します。送っていない書きかけがあれば、消すか残すかを聞きます（無ければ、サーバー版と同じく聞かずにログアウトします）。パスキーはパスワードの管理（iPhone なら設定 → パスワード）に残るので、要らなければそこで消してください
- 「ログアウト」で書きかけを残したときは、書きかけごとに、書いたブランチと送る頻度を残します。作品ごとのリポジトリの ID も残します（ログアウトしている間に GitHub でリポジトリの名前が変わり、もとの名前で別のリポジトリが作られても、書きかけをそこへは送りません）。トークンを入れ直して作品を開くと、アプリはそのブランチと送る頻度で作品を開きます。書いたブランチが GitHub にもう無いときも、アプリは書きかけをほかのブランチへ自動では送りません。「送る」を押すと、いまのブランチに送るかを確かめます。「⎇」では、書いたブランチにだけ切り替えられます（無ければ作ります）
- GitHub がトークンを断ったとき（期限切れなど）は、この端末の作品の控え・設定・記録・書きかけを消しません。トークンを入れ直せば、作品は前と同じブランチと送る頻度のまま続きます（サーバー版の NFR-SEC-16 との違いと理由は [DESK-SEC-03](docs/requirements.md)）
- 書きかけの持ち主は、GitHub のアカウントの番号で覚えます。トークンなら GitHub のユーザー（API の `/user` の `id`）、GitHub App なら App を作ったアカウント（API の `/app` の `owner.id`。App を入れられるのは作ったアカウントだけなので、入れた先のアカウントと同じです）です。同じアカウントなら、App を作り直したときも、トークンから App に替えたときも、同じ人として書きかけを続けます。前の版で覚えた形（ユーザー名、または「app:」と App の ID）からは、ユーザー名が同じか、App の ID か Client ID が同じなら、同じ人とします
- 書きかけを残したまま、別のアカウントのトークン（または別のアカウントの GitHub App の秘密鍵）を入れたときは、中身を出さずに、前の人の書きかけを消すかを聞きます。消さないなら、そのトークン（秘密鍵）は保管しません
- 作品の画像として出すのは、JPEG、PNG、WebP、GIF だけです（SVG は出しません）
- ページには CSP を付けています。スクリプトはこのサイトのものだけを実行し、通信先は `https://api.github.com` だけです
- この端末に残す版（履歴）は、話ごとに新しいものから 100 個までです

## 読む novel.toml の項目

- `title`: 作品の題名
- `manuscript.dir`: 本文のフォルダ。中の「番号_題名.md」が話、「番号_題名/」が章
- `manuscript.files`: 話にするファイル名（例 `"[0-9][0-9].md"`。配列も可）
- `manuscript.exclude`: 話から外すファイル（本文のフォルダからのパス）
- `manuscript.title = "heading"`: 話の題名を 1 行目の「# 第1話 題名」から取る
- `manuscript.naming = "chapter-number"`: 「2-09.md」を第 2 章の第 9 話として読む
- `manuscript.naming = "number"`: 新しい話と章を番号だけの名前にし、題名を `[titles]` に書く
- `[titles]`: 話や章の題名（本文のフォルダからのパスをキーにする）
- `git.branch`: 読み書きするブランチ（書いていないときと、GitHub にそのブランチが無いときは、リポジトリの既定のブランチ。無いときは、そう知らせます）
- `[notes] dir`: 資料のフォルダ
- `[images] dir`: 画像を置くフォルダ
- `[plot] file`: プロットにする資料。`[plot.links]`: 話（本文のフォルダからのパス）と中箱（見出し）の対応。話を動かすと、キーも一緒に動かします
- `[characters] file`: キャラクターの資料

ほかの項目は読み飛ばします。読めない形の novel.toml（文字列を "" で囲んでいない、複数行の文字列など）は、
何行目の何が読めないかを目次の上に出し、本文のフォルダを一番上として読みます。

## できないこと

サーバー版の要件のうち、サーバーが無いとできないものと、その理由です。

- GitHub のアカウントでのログイン（FR-AUTH-01）: GitHub の OAuth でユーザーのトークンを受け取る口（`github.com/login/oauth/access_token`、デバイスフローの `github.com/login/device/code`）が、ブラウザーのページからの要求（CORS）を受け付けないためです。受け取るには、ページの代わりに要求を送るサーバーが要ります。この版では、作者のアカウントに GitHub App を作り（manifest flow。App を作ったコードの受け取りは、`api.github.com` なのでブラウザーから要求できます）、その秘密鍵でインストールのトークンを受け取ります。トークンを手で作らずに GitHub と連携すること（FR-GH-01）は、この方法でできます。作者が fine-grained トークンを作って入れることもできます（どちらでも、別のユーザー名とパスワードは作りません）
- 管理者、ユーザーの登録の許可と停止、ユーザーの無効化、初回セットアップのリンク、緊急用のログインリンク（FR-AUTH-02〜06）: アカウントを預かるサーバーが無く、ユーザーという考えがありません。誰がどの作品を読み書きできるかは、GitHub のトークンの権限で決まります（FR-AUTH-08 は GitHub が受け持ちます）。ログアウト（FR-AUTH-07）は「ログアウト」のボタンで、この端末からトークンと作品の控えを消します
- ページを閉じている間に送ること、毎日決まった時刻に送ること（FR-SAVE-03 のうちページを閉じている間、FR-GH-03）: 送る処理はこのページの中で動くので、ページを閉じている間は何も動きません。決まった時刻に動かすには、サーバーが要ります。ページを開いている間は、書く手を止めたときと画面を離れたときに自動で送ります
- 同期が続けて失敗したときの知らせ（OPS-08）: 閉じているページから知らせるには、通知を送るサーバー（Web Push）が要ります。開いている間は、送れなかったことと理由を画面に出します
- CSP の frame-ancestors（NFR-SEC-08 のうち）: GitHub Pages では応答にヘッダーを付けられず、frame-ancestors は meta の CSP では効きません。ほかの CSP（スクリプトはこのサイトのものだけ、通信先は api.github.com だけ、object-src 'none'、base-uri 'none'、form-action 'none'）は meta で付けています
- サーバーの性能・セキュリティ・運用の要件（NFR-PERF-01・02・04、NFR-REL-02〜05、NFR-SEC-01〜04・06・09〜14・17〜19、NFR-PORT-02〜05、OPS-01〜19）: サーバーとそのマシンについての要件で、サーバーが無いこの版には当てはまりません

## 作者の判断で当てはめない要件

- 古い形式の作品を開くこと（FR-WORK-07。`.novel.json` の作品、`_没/` のフォルダ）: 作者の判断で、この版では扱いません。作品は `novel.toml` の形式で置きます（[DESK-WORK-01](docs/requirements.md)）

## 開発

開発用のツールだけを npm で入れます。アプリ本体はライブラリを使わず、ビルドもしません。

```sh
npm install
npm run serve       # http://localhost:4173/ で開く
npm run check:all   # 整形、書き方、型、サーバー版との違い、単体試験（lib は 100%）、画面の試験（Chrome と WebKit）、画面の JS のカバレッジ 100%、保存の処理の変異テスト、トレース検証
```

- 決める部分は `lib/` の純粋な関数にし、vitest で試験します（`tests/unit/`。行・分岐とも 100%）
- 画面は Playwright で試験します（`tests/ui/`）。GitHub の API は偽物（`tests/ui/lib/fake-github.mjs`）で、本物の GitHub には通信しません
- 画面の JS（`app.js`、`boot.js`、`sw.js`、`ui/`、`lib/`）は、画面の試験と単体試験を合わせて、全部の行と分岐を通します（NFR-MAINT-02）。画面の試験では、`tools/serve.mjs` がスクリプトを istanbul で計測できる形にして出し、`tools/coverage_all.mjs` が単体試験の記録と合わせます。通っていない所は `coverage/all/missing.txt` に出ます
- 書いたものを残して送る処理（`lib/` の changes・drafts・merge・sync）は、Stryker の変異テストで、コードを少し変えた変異を単体試験が全部見つけることを確かめます（`npm run test:mutation:save`、NFR-MAINT-02）。`lib/` 全体の変異テストは `npm run test:mutation` で、結果は `reports/mutation/` に出ます（サーバー版と同じく、全体には止める基準を付けていません）
- 送る処理と読み込みは、fast-check の性質の試験でも確かめます（`tests/props/`、`npm run test:props`）。本物の `ui/send.js`・`ui/work.js` と `lib/` を、画面の試験と同じ偽物の GitHub につなぎます。1 つは、GitHub の答えが返る順番を fast-check が選び、その間に打った文字とほかの所での書き込みを混ぜます。もう 1 つは、打つ・話の追加・名前の変更・削除・並べ替え・送る・読み直す・ほかの所での書き込みを、でたらめな順番で続けます。どちらも、書いた文字が消えないこと、手で書いた novel.toml の行がそのまま残ること、送る処理が意図しないファイルを消したり変えたりしないことを確かめます。check:all では種を固定して実行します
- 送る処理の並行の動き（送っている間の入力、ほかの所で進んだブランチへの送信、送っていない操作の取り消し）は、`formal/` の TLA+ のモデルで、文章が消える順番が無いことを確かめます。モデルとコードが合っていることは、画面の試験の記録をモデルの手順でたどるトレース検証で確かめます（NFR-MAINT-03、`formal/README.md`）。TLC には `formal/tla2tools.jar`（コミットしません）と、Java か podman が要ります
- WebKit は Playwright の Docker イメージで実行します。`NW_NO_WEBKIT=1` で WebKit を外せます
- パスキーの試験は Chrome の仮想認証器で実行します。WebKit には Playwright から操作できる仮想認証器がないので、Chrome だけで実行します
- オフラインの試験も Chrome だけで実行します。WebKit では、service worker が付いたページの通信を Playwright の route が受け取れず、偽物の GitHub に届かないためです

ファイルの置き場所は次のとおりです。

- `index.html`、`style.css`、`app.js`: 画面と、トークン・リポジトリの選択（`style.css` はサーバー版のものをそのまま使い、Novel Desk だけの部品の規則を後ろに足しています）
- `boot.js`: ページが出る前に実行すること（iOS の拡大を止める、画面の色、モジュールが動かなかったときの読み込み直し）。サーバー版は index.html の中に書いています
- `docs/`: Novel Desk だけの要件（`requirements.md`）と、サーバー版との違い（`server-differences.md`）
- `tools/server_diff.mjs`、`tools/server-diff-allowed.txt`: サーバー版の `style.css` と `index.html` と比べる点検（`npm run check:server`）と、理由のある違いの一覧。サーバー版のフォルダは `NOVEL_WRITER_DIR`（無ければ `~/novel-writer`）で、`git show` で読むだけです
- `ui/`: I/O の層（IndexedDB、パスキー、GitHub の API、目次と本文、送る処理、入力補助のバー、プレビューと前後の話、画像、履歴、資料、プロット、キャラ、横の資料、記録、リリース、ブランチ、未送信の一覧、トレース検証の記録）。`ui/shared.js` は、書く画面（desk.js）がほかの画面に渡す窓口です
- `lib/`: 純粋な関数（TOML とその書き換え、novel.toml と目次、未送信の変更、話の追加・題名の変更・削除・並べ替えの決まり、資料と画像、プロット、キャラ、記録、リリース、ブランチ、差分、Markdown、commit メッセージ、積み直し、文字コード）
- `sw.js`、`manifest.webmanifest`: オフライン用の控えと、ホーム画面に追加するための設定
- `formal/`: 送る処理の TLA+ のモデルと、トレース検証のモデル（`tools/trace_check.mjs`、`tools/trace/`）
